Panel Assistant 1.0.1 is the first update after 1.0. Its biggest fix is to WebView updates started from Home Assistant, which in 1.0.0 never got as far as downloading the WebView. It also makes proximity optional, so a panel can learn its sensor from your touches, and it gives slow update copies more time and clearer answers. These notes cover what you will notice since 1.0.0; if something does not work on your panel, please open an issue with the panel model and what you saw.

Pairs with the 1.0.1 Android app, which each panel is offered as an update. Panels on the 1.0.0 app keep working.

### New

- **Presence select.** With the 1.0.1 Android app, each panel has a Presence select (Automatic, Home Assistant device, Manual (setup wizard), Hybrid or Off) that matches the panel's new Presence setting, so an automation can change it. A panel that is still learning its proximity sensor from your touches no longer raises the proximity setup Repair.
- **Android app release notes in the update dialog.** A panel's update in Home Assistant now shows a short summary of what changed in the Android app, with a link to the full notes.
- **A clear answer for a panel that never signed in.** A panel that answers on the network but has not finished signing in to Home Assistant used to show as online with only a few entities and no sidebar page. After two minutes its status now reads Not signed in to Home Assistant, and a Repair links to the panel's setup page. Both clear as soon as the panel connects, and a panel that has connected before never gets them.
- **Owner hardware report.** Configure on any panel offers Owner hardware report, which opens a prefilled GitHub issue with the panel's non-identifying hardware details for you to check and complete. Nothing is posted until you submit it on GitHub.
- **USB debugging steps for Shelly Wall Displays.** Before you connect a Shelly Wall Display, the USB installer shows the taps that turn on USB debugging. They were confirmed on earlier X2i firmware and some owners report they no longer work on 2.8.4, so the installer says to ask Shelly if they do not open developer options.

### Fixed

- **WebView updates finish.** In 1.0.0 the panel turned down the WebView request that Panel Assistant sends with an update, so a Android app update or a WebView-only update started in Home Assistant ended with an unfinished WebView Repair, and Try again repeated it. The panel now downloads and installs the WebView. When a panel will not take a new WebView, for example because it is already current or short of storage, the Repair goes away instead of offering a retry that could only fail, and when the panel cannot tell how an install ended the Repair stays so you can try again.
- **WebView Repairs say what to do.** When a WebView update does not finish, the Repair explains the panel's reason in plain words, links the update guide for your panel model and keeps that reason in the support report.
- **Slow update copies finish or say why.** Copying the app to a slow panel is no longer cut off after three minutes while it is still moving, and a copy that stalls for 30 seconds stops. Its Repair says how fast the transfer ran and suggests restarting the panel. If Home Assistant restarts while an update is still copying, the Repair offers Try again.
- **Fresh installs finish on more panels.** When a panel's own launcher stays in front of the setup screen after a network install, or a Shelly Wall Display is left on Android's home screen chooser, the install now completes and leaves setup to the panel instead of ending with a warning that the install may have changed the panel.
- **A panel on IPv4 and IPv6 is offered once.** Discovery now offers such a panel by its IPv4 address, so it no longer appears twice under different addresses, and adding it from one card works even if you ignored the other.
- **Update checks are lighter.** Checking whether Panel Assistant can reach a panel for updates closes its connection even when the panel does not answer, no longer delays Home Assistant's startup, and runs every ten minutes or on reconnect instead of on every health update.
- **Renaming an entity ID keeps it working.** On Home Assistant 2026.11, a renamed panel entity keeps its live updates, camera stream, announcements and timers.
- **The sidebar shows your theme's background.** Panel Assistant's sidebar no longer paints its own background over the one your Home Assistant theme sets.

### Changed

- **Proximity setup is optional and its Repair can be ignored.** The proximity setup Repair now says that proximity is optional and that touching the screen always wakes the panel. You can select Ignore, or turn off Wake on wave, and it stays ignored. It still clears itself once the panel saves a calibration.
- **Fewer Repairs for a dashboard that is briefly unfiltered.** A panel that shows its dashboard without entity filtering usually filters again within minutes, so this is now a warning in the Home Assistant log, and the Repair appears only when the dashboard is still unfiltered after 30 minutes.
- **Less root use on rooted panels.** With the 1.0.1 Android app, routine repairs and the home screen hand-over on a rooted panel use a small set of fixed commands the Android app offers instead of shell programs run as root.
