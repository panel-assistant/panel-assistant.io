Panel Assistant 1.0.2 is a small update after 1.0.1. Its main fix is for installs: an install that never finished could stop you adding the panel at all, with an error about the installation receipt that explained nothing, and now you get a choice instead. It also keeps network ADB working after a restart on more panels, shows one discovered card for a panel heard at two addresses, and offers the WebView again after a rollback. These notes cover what you will notice since 1.0.1; if something does not work on your panel, please open an issue with the panel model and what you saw.

Pairs with the 1.0.2 Android app, which each panel is offered as an update. Panels on the 1.0.1 app keep working.

### Fixed

- **An unfinished install no longer blocks its panel.** Panel Assistant keeps a record of each install it starts. If one never finished, adding the same panel another way, by its IP address after its host name, from a second discovered card or after the panel moved network, was refused with "could not safely load or persist the installation receipt", and nothing was written to the log. The record never expired, so restarting Home Assistant or reinstalling Panel Assistant made no difference. Now the dialog says This panel has an unfinished install and offers Carry on with that install or Cancel it and start again, and cancelling removes nothing from the panel. An install nobody is working on ends by itself after 15 minutes without progress, and an install that worked but was never added to Home Assistant is let go after a day: the Android app stays on the panel, no Repair is raised, and you add the panel like any other. Every refusal in the setup dialog is now written to the Home Assistant log with its cause. The new dialog is in English for now.
- **Network ADB stays on after a restart.** On a panel whose ADB runs as root, the Android app keeps network ADB, the connection Panel Assistant uses to install and update it, on across restarts, but only once it has run. A network install that stopped before then could leave the panel without network ADB after its next restart, so Panel Assistant could no longer reach it. The install now sets the panel to keep network ADB after a restart just before it starts the Android app, unless the panel already has its own setting, which is never changed.
- **One discovered card per panel.** A panel on another part of your network could appear twice under Discovered, once as Android followed by its serial number and once under its own name, and adding it from both cards started two setups. Each card now remembers every address the panel announced, and once the Android app answers as the panel, the other card for it closes. In most cases a panel now shows one card, and separate panels stay separate.
- **The WebView is offered again after a rollback.** When a panel's WebView went back to an older version after an update, Panel Assistant stopped offering the WebView update for it. It now offers it again, and the 1.0.2 Android app no longer restarts itself about every 30 seconds in that state.
- **Proximity learning finishes without another touch.** With the 1.0.2 Android app, a panel learning its proximity sensor in Automatic starts using presence and wave as soon as it has seen the empty room, instead of waiting for another touch, and keeps what it learned across a restart.
- **Screen wake and microphone tuning.** With the 1.0.2 Android app, a tap on a screen that was turned off on purpose and did not wake tries again instead of being ignored, and Cancel in Tune the microphone stops cleanly, so the panel answers its wake word straight away.
- **Setup carries on by itself.** With the 1.0.2 Android app, after you sign in to Home Assistant on the panel, a panel with a setup question still open goes straight back to its setup wizard, and choosing Use this dashboard in the wizard finishes setup instead of leaving it half done.

### Changed

- **The on-panel sign-in names the panel.** With the 1.0.2 Android app, Home Assistant's sign-in page on the panel shows the panel's address on your network instead of 127.0.0.1, so you can tell which device is asking.
