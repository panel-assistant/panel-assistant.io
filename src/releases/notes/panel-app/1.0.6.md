This update fixes delayed keyboard taps, dashboard reconnects and settings imports, and sets up a panel moved over from the Companion app the same way as a new one. If something misbehaves, please open an issue with the panel model and what you saw.

Pairs with Panel Assistant 1.0.6, the Home Assistant integration.

### Fixed

- **Keyboard and Configure.** Swipe reveal no longer delays taps on the bottom row of the on-screen keyboard. Configure stays at the setting you just changed ([android #211](https://github.com/panel-assistant/android/issues/211)). Text fields fit in their cards, help stays open after a quick click, and narrow pages are easier to use with enlarged browser text. Thanks to [@jpbaril](https://github.com/jpbaril) for reporting the keyboard delay and the scroll jump.
- **First setup.** New setups turn on the dashboard entity filter when it applies, and the setup Repair asks about it if setup still needs an answer. With the dashboard as the home screen and Launcher set to Auto, the Launcher button opens the panel app's launcher.
- **Dashboard.** The dashboard retries after a refused Home Assistant connection while the screen is on. Coming back to the dashboard rebuilds a browser renderer that stopped while it was hidden. Setup asks again if it could not save your dashboard answer. Auto sleep refreshes when you put the panel in a Home Assistant Area.
- **Settings and updates.** A settings import without sign-in details keeps your current sign-in when the Home Assistant address stays the same, and a full import can still sign the panel out. An import with nothing usable in it is refused instead of applied. The app clears leftover uploads of the version already installed.
- **Profiles and diagnostics.** Startup skips incompatible replacements for a pinned bundled profile. Ordinary compatibility checks and repeated diagnostics log fewer warnings.
- **Proximity.** Configure brings the proximity settings into view and keeps them highlighted long enough to see.
