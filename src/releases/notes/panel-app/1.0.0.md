This is the panel app's 1.0, the Android app that Panel Assistant installs on your panels. The story of 1.0 is that MQTT and the old app are gone for good. In exchange the panel and Panel Assistant now talk over one connection for everything, including the sidebar, updates, logs and voice, and that is what makes most of the changes below possible. A lot changed since v0.9.11, so I have listed what you will notice rather than every commit. If something breaks, please open an issue with the panel model and what you saw.

Pairs with Panel Assistant 1.0.0, the Home Assistant integration.

### Before you update

- **A panel still on MQTT has to go through Panel Assistant 0.9.0 first.** 1.0.0 has no MQTT path. Panel Assistant 0.9.0 moves every panel to the native connection and off the old app, so let it finish that with every panel on v0.9.11 before you install Panel Assistant 1.0.0. A panel still on MQTT or the old app is refused, with a Repair that takes you back through 0.9.0.
- **Update Panel Assistant to 1.0.0 first.** It speaks only the new connection, and it then offers this release to your panels as a normal update.
- **There is no way back to 0.9.** Android does not install an older build over a newer one. Take a settings backup from the panel's Install page before you update if you want one.
- **From 1.0.0 on, rooted panels no longer need network ADB.** Panel Assistant now sends its update and maintenance commands to a rooted panel over the panel's own connection, and switches network ADB off while it manages the panel; the ADB switch on the Configure page says so. If you use network ADB on a rooted panel yourself, removing the panel from Panel Assistant turns it back on.
- **From 1.0.0 on, a panel Panel Assistant cannot reach over ADB updates with one tap on the panel.** Install and update now give the panel app permission to install packages, so a panel without network ADB installs its own update after someone taps Install in Android's confirmation on the panel. Reconnecting the panel by USB brings back updates that need no tap. This update itself still arrives over network ADB, so a panel on v0.9.11 without it needs reconnecting with Panel Assistant's USB installer first.
- **Two entities are gone.** The separate camera snapshot image entity and the panel's snapshot.jpg address are removed; use the panel's camera entity, which takes snapshots from the camera stream. On a panel with a speaker the separate volume number is removed; use the media player's volume. Automations that used either need changing; for the volume number, Panel Assistant raises a Repair naming the automations and scripts that still use it.

### New

- **See the voice conversation on screen.** After the wake word, a card at the foot of the dashboard shows whether the panel is listening, thinking or replying, quotes what it heard, writes out the reply as it arrives and ticks off Heard, Understood and Answered. If something fails, the card says what went wrong in plain words.
- **Say "stop" to end a reply, an announcement or a ringing timer.** While the panel thinks or speaks it also listens for "stop", silences the sound and goes back to waiting for the wake word. A voice request Home Assistant does not pick up within four seconds now gives up instead of hanging for two minutes.
- **Panel Assistant can update a panel's WebView.** During installation, during a panel app update you start in Home Assistant, or through a Repair you start, Panel Assistant installs the newest known-good Android System WebView for that panel model and checks it before use. A too-old browser engine no longer stops setup, so pairing can finish first and the update can follow. It never downgrades the WebView or replaces one the Play Store keeps up to date.
- **Panel voice commands.** Say "show the kitchen page", "show Android settings" or "show the launcher" to the panel you are speaking to, in every language Panel Assistant ships.
- **Download community wake words.** The Voice card on the Configure page offers community wake words from a list that ships with the app. It shows each one's author and licence before downloading, shows progress, and checks every file against the list before using it.
- **Show dashboard and Back from Home Assistant.** Each panel offers a Show dashboard button, which brings the dashboard to the front, and a Back button, which does what Android's Back does. Back is offered only while the panel can perform it: its accessibility service is running, or the panel is rooted.
- **Dashboard theme, idle return and screen timeout from Home Assistant.** Home Assistant can show and change the dashboard theme, the idle return to home and Android's screen timeout, which is the screensaver delay on a TV, and a change on either side shows on the other at once. The screen timeout can be changed only while Prevent idle dim is off.
- **Panel logs through Panel Assistant.** When you choose a log destination under Panel Assistant's Panel logs (all panels) option, every panel sends its logs there through its connection to Home Assistant, and goes back to its own log settings when that connection ends.
- **Screenshots and display sizing on panels without root.** On Android 11 or later, a panel without root, such as the Shelly Wall Display X2i, now shows its live screenshot in Panel Assistant, and a tap on it reaches the panel and comes back with a fresh picture. Text size and display density can be set from the Install page on the same panels, where the firmware allows it. None of this uses ADB.
- **Meta Portal support.** The panel app now recognises the Meta Portal 10-inch (2nd gen), with its camera, microphone, light sensor and native screen density, and other Portal models through a family profile. On a Portal the screen sleeps through Android's screen timeout, the panel launcher opens instead of Meta's clock, the hardware microphone privacy switch is followed, and the panel app stays the home screen even where Meta's firmware keeps showing Android's Home chooser. The name you give the panel also becomes the Portal's own device name, and the panel app's own notices and pages on the Portal use the same Roboto font as every other panel.
- **Entity reading shows its progress.** Setup and the panel's hold screen show an approximate entity total and a progress bar when Panel Assistant supplies the count or the panel has a previous scan. The final count replaces the estimate when reading finishes.
- **Panel models start with their own sensible defaults.** Each panel model's profile can now set starting values, such as dashboard zoom and brightness range, and recommend a display size; a Meta Portal 10 starts at 85 percent dashboard zoom, for example. A setting you have already changed keeps your choice.
- **Press and hold on hardware keys.** A panel model's profile can now have a key report its release as well as its press, so an automation can tell a hold from a tap. The Smatek S9E's F1 to F4 keys do this on a panel with the root helper.
- **Smatek S9E room temperature and humidity.** The S9E now reports the room temperature and humidity from its built-in sensor.
- **A panel's device links to the same hardware in other integrations.** The panel now reports its Wi-Fi and Ethernet hardware addresses, and Panel Assistant adds them to the panel's device, so a device another integration made for the same panel, such as the Shelly integration's for a Shelly Wall Display, shows as linked on the device page.
- **USB debugging shows as a diagnostic.** Home Assistant now shows whether USB debugging is on for each panel as a diagnostic entity, so you can see whether a panel can still be reached for updates, and the panel shows a notice on screen when it changes.

### Changed

- **MQTT is removed.** The panel app no longer has a broker setting or an MQTT step in setup: every panel talks to Home Assistant through Panel Assistant's own connection, and button presses, auto-sleep activity, the camera and Zigbee gateway health reach Home Assistant that way.
- **The Panel Assistant sidebar shows the panel's own pages over its connection to Home Assistant.** In the sidebar, the panel's pages now load and talk to the panel through its existing Home Assistant connection instead of Home Assistant fetching them from the panel, so a panel that Home Assistant cannot reach directly, on another network segment or behind a firewall, can still be viewed and configured from the sidebar. While the panel restarts the sidebar retries on its own. Opening the panel at its own address works as before.
- **Settings apply as you change them.** The Configure page no longer has a Save button: each change is sent as soon as you make it, a change made from Home Assistant or another browser shows on the page within a second, and the page says whether a change is already on the dashboard or still being applied.
- **Voice starts on where the panel has a known microphone.** A panel whose model has a proven microphone, such as the Sonoff NSPanel Pro, the Electron WF1589T, the Tuya TPA10, the Shelly Wall Display X2i and the Meta Portal 10, starts with the voice assistant on. A panel where voice was already turned on or off keeps that choice. Enabling the panel's Assist entity in Home Assistant turns the voice assistant on too.
- **Home Assistant's menu button is back on every panel.** Home Assistant's menu button and sidebar are shown again on every panel after this update, including panels where they had been hidden. You can hide them again with Hide Home Assistant navigation (native) on the Configure page's Built-in renderer card, and that choice is kept from now on.
- **The panel app becomes the home screen only once setup is finished.** Until then the panel keeps its own launcher, and an abandoned setup hands the home screen back and can be uninstalled from Android Settings. Removing the panel app returns the panel to the home screen it had before, and on a rooted panel also stops and removes the app's root helper.
- **Entity filtering is tighter and never leaves you without a dashboard.** A filtered dashboard now also hides the devices and registry entries of entities it does not allow, and learns which entities a template card uses before it first draws. The Entities page shows when the panel is holding the dashboard while it learns, and if the filter is not ready after 90 seconds the panel shows the dashboard unfiltered and switches to the filtered one once it can.
- **Shelly Wall Display screens switch fully off.** On a Shelly Wall Display, including the X2i, the panel app now turns the backlight off through Shelly's own launcher instead of only dimming it, and the first touch on the dark screen wakes it without pressing anything on the dashboard. Shelly's own auto-brightness is kept off so the brightness you set is the one shown. A newly set up Shelly Wall Display starts with the navigation bar on Swipe reveal: swipe up from the bottom edge to show it.
- **Choosing the dashboard in setup is one tap.** When your Home Assistant account has no default dashboard, the panel's setup now starts on Home Assistant's own Overview instead of an empty choice, and setup lists Home Assistant's built-in dashboards by the names Home Assistant gives them.
- **The panel's web page finds a free port.** It moves to a free port if another app already uses 8888, and Panel Assistant follows it there.
- **Clearer names in Android's Home app list.** The panel's own app drawer is now called Panel launcher instead of Panel admin, and the dashboard entry is called Home Assistant Dashboard instead of HA dashboard, in Android's Home app list, its Home chooser and the Launcher app setting.
- **Panel app updates belong to Panel Assistant.** The panel app's own Install page no longer offers a separate panel app version picker; choose its update in Home Assistant. Updates are compared by build number alone, so a newer build is never refused as a downgrade because its version name sorts lower.
- **Uploaded wake words need approval in Hardened mode.** Importing your own wake word through the panel's web address now asks for approval on the panel, which requires physical access and cannot be approved remotely; downloads from the community list and imports through a Home Assistant administrator's sidebar keep working without that extra step.
- **Tidier panel web pages.** Every warning and advisory on the panel's pages uses one notice style, long field instructions and choice lists wrap instead of being cut off, the auto-sleep activity source and the Home Assistant Companion version are picked from a pop-up menu, the wording is consistent and uses Home Assistant's own terms, and the Pickles artwork is refreshed.

### Fixed

- **No more "Login attempt failed" on every install.** Checking the Home Assistant address during installation made Home Assistant show a failed-login notification naming the panel and count it towards an IP ban. The check now uses a request Home Assistant answers without a login.
- **The panel says when, and why, it cannot reach Home Assistant.** When the dashboard drops and the panel has no session to Panel Assistant, it shows Cannot reach Home Assistant with a retry timer instead of a bare Offline, and names the cause, such as refused, timed out or a name that does not resolve, and the address it tried. The reconnect card also comes back correctly after the dashboard's browser engine crashes or the screen goes dark mid-load.
- **A refused fallback address no longer ends sign-in.** A panel whose sign-in is refused on one of its fallback addresses, such as a cloud address for a Home Assistant user who may only sign in locally, no longer stops at "Home Assistant sign-in rejected". It rules that address out and goes back to its other addresses, including the one you configured.
- **No more dashboard stuck on Preparing.** After an update, a theme change or choosing a new home dashboard, the panel brings its existing dashboard forward instead of opening a second copy that could sit on Preparing dashboard until Home was pressed.
- **The panel's dashboard theme is respected.** Choosing Dark or Light for the panel's dashboard now works even when the panel's Home Assistant user has its own theme saved, and on panels running Android 9 or older, such as the Sonoff NSPanel Pro. The loading screen and first paint follow it too.
- **Too-old WebView warnings point to the fix.** The setup page in a browser names Android System WebView and links the update steps for your panel model, and the System WebView warnings on the Dashboard and Install pages open those same steps. The panel's own setup screen says its browser engine is too old at every step, and that setup can still finish.
- **The navigation bar behaves on Android 8.1 panels such as the Sonoff NSPanel Pro.** It follows its mode and sits on the bottom edge of the screen; once set to Always on it could not be changed, and it could be drawn a bar-height above the edge with an empty band beneath it. The bar's Launcher button opens the panel launcher every time.
- **Kiosk mode reports and keeps its real state.** Turning kiosk mode on or off quickly, or when the panel's storage refuses a write, no longer leaves the panel locked when it shows unlocked or the reverse, and the way out of kiosk mode always works.
- **Home Assistant shows panel sensors accurately.** A sensor you hide on the panel's Configure page becomes unavailable in Home Assistant straight away, a sensor with no reading shows as unknown together with the reason, and the light-sensor picker says when sensors were found but none is reporting a light level. A panel model with no physical keys, such as the Shelly Wall Display X2i, no longer gets a button entity that would stay unknown forever.
- **The Smatek S9E switches its backlight off.** Switching the screen off used to dim it to black with the backlight still lit, and the screen switch in Home Assistant could turn itself back on a few minutes later. The panel app now powers the S9E's backlight off, the switch stays off, and a touch still wakes the screen.
- **The restart notice is more reliable.** While Home Assistant restarts, the notice says so when the restart runs past its usual time, even while the dashboard reloads, gives way if Home Assistant never comes back, and survives a refresh of the connection to the same Home Assistant.
- **Panel Assistant can remove the app when it is a device admin.** Android refuses to uninstall an app that has been made a device admin in its settings, so removing the panel app failed on such a panel. The app now gives up device admin when Panel Assistant asks, just before removing it.
- **No more refusal to start after a fresh install.** A freshly installed panel app no longer refuses to start now and then, reporting its new settings database as too old.
- **Setup follows a panel that changes address.** If the panel's network address changes during setup, its setup QR code and the sign-in address shown for your phone update to match, and a sign-in that was refused is not retried when the network comes back.
- **Screen and area changes apply as reported.** Switching auto-sleep on from the Configure page takes effect at once, a touch reliably wakes a screen switched off through the screen timeout, and when Panel Assistant reports that the panel moved to another Area the panel reads its Area again straight away; an Area chosen on the panel itself is still kept.
- **The media player's volume no longer goes blank.** On a panel with a speaker the volume is always reported to the media player, so hiding Panel volume can no longer blank it.
- **Proximity calibration is kept.** A panel's saved proximity calibration now survives app updates and a backup restore, and turning on Wake on wave on a panel without a proximity sensor reports it unavailable instead of pretending.
- **Proximity setup no longer saves a boundary that stops working after a day.** A proximity sensor's reading from an empty room moves with light and temperature, by tens of counts over a few days. Setup used to place the near/clear boundary a fixed share of the way between its two readings, so a weak approach put it inside that movement, and within a day the panel decided someone was always there: it stopped going to sleep on its own and a wave could not wake it. Setup now keeps the boundary clear of the movement measured for the panel's kind of sensor. When your normal position reads too close to the empty room for that, setup says so on the panel, leaves presence off and goes on to test a hand wave from where you stand. On panels whose sensor reads a person only a little above the empty room, such as the Sonoff NSPanel 86 and the Tuya TPA10, a setting saved earlier is kept as it was. On other panels a setting saved earlier that sits inside that range is set aside, untouched, and the panel offers proximity setup again; until then it does not use proximity to sleep or wake, and touch-to-wake is unaffected.
- **Backups and restores say what happened.** Restoring onto a panel without root lists the settings it cannot apply instead of failing, a setting still being applied is listed as pending, and in Hardened mode the Install page tells you where to approve a restore on the panel and whether approval was denied or timed out. Several backup downloads no longer get the same name.
- **Configure keeps your place.** In the sidebar, Basic or Advanced, Descriptions, expanded settings and the setting filter survive a reload or a switch to another panel, Basic view keeps a blocked setting's prerequisites within reach, and Reconnect opens Home Assistant sign-in in a separate window and follows the new account once sign-in finishes.
- **The sidebar shows the last screenshot straight away.** The Dashboard page shows the panel's last screenshot while a fresh one is taken, so a sleeping or slow panel no longer leaves the card empty.
- **The Info page's process lists are right.** The CPU and memory lists no longer show a newly started process under the name and usage of one that has already ended, busy system processes no longer go missing, and a process name with quotes or other special characters no longer breaks the readings.
- **Voice settings stay current.** The list of voice pipelines is fetched again when the panel's Home Assistant connection changes, and a new audio source takes effect as soon as the camera stream lets go of the microphone.
- **Vendor apps are tamed on the first try on a slow panel.** On a panel whose root helper is slow to stop or disable an app, the taming pass no longer runs each action twice and repeats for several minutes after the app starts.
- **Log shipping reports an outage once.** While the log collector cannot be reached, the panel logs the first failed attempt and, when it reconnects, one line saying how many attempts failed and the last reason. Logs queued during the outage keep the time they were captured.
- **Translation corrections** across every shipped language, including the setup screens, the Voice card, the diagnostics page and labels that wrapped in the sidebar.
