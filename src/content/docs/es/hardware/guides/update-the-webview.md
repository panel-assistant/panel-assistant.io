Lee esto antes de nada: un WebView obsoleto es el fallo más habitual en el primer inicio de estos paneles.

El renderizador integrado depende del **WebView del sistema** Android. La mayoría de paneles trae uno demasiado antiguo para el frontend actual de Home Assistant. Puede dejar la pantalla en blanco o rota, tarjetas ausentes o «navegador no compatible». Los paneles **sin** Google Play (Sonoff NSPanel Pro, Tuya TPA10) necesitan otra vía. **Electron WF1589T y ZHICAI SMT1019 tienen Google Play**: actualiza _Android System WebView_ desde Play Store o usa su canal de desarrollo de WebView.

La instalación y las actualizaciones de la app iniciadas desde Home Assistant también pueden instalar un WebView compatible verificado. Requiere perfil compatible, proveedor no gestionado por Play con el mismo paquete y firmante que la compilación elegida y una ruta de instalación permitida. Si queda sin terminar, elige **Reintentar** en la reparación de actualización del panel. Comprueba el trabajo existente antes de solicitar otro intento; no hay reintentos programados. Un motor antiguo no impide configurar y emparejar, pero puede seguir sin mostrar el panel de control. El proveedor original del TPA10 bloqueado por firma sigue necesitando el intercambio root documentado antes de usar uno con firma distinta.

## Alternativa manual

Usa el método existente de tu panel si no está disponible la vía gestionada. Instalar directamente por adb Android System WebView (paquete **`com.android.webview`**) requiere una compilación para la versión Android y ABI del panel, sin tiendas de terceros.

:::tip
El paquete debe llamarse `com.android.webview` para que el sistema lo seleccione automáticamente. Las compilaciones **SystemWebView** de Cromite y LineageOS usan `com.android.webview` y se registran como proveedor, pero el **navegador** Cromite normal usa otro paquete y no lo hace. Usa SystemWebView, no el APK del navegador.
:::

## Instalar manualmente y verificar

1. Descarga un APK actualizado de **Android System WebView** con paquete **`com.android.webview`**. Se recomienda **LineageOS** System WebView: 138 es el último para Android 8.1 y 150 cubre Android 10 y posterior; ambos están en el espejo. Es Chromium sin modificar y no lleva el bloqueo de reproducción automática de Cromite que detiene las cámaras de Home Assistant. El paquete `com.android.webview` hace que se seleccione automáticamente como proveedor, sin editar listas ni otra app, y se redistribuye libremente. Usa la ABI de tu panel.

   :::caution
   La instalación simple siguiente funciona si la ROM omite la comprobación de firma WebView, como `userdebug` del NSPanel Pro. **Los paneles con firma bloqueada, incluido TPA10 y probablemente otras compilaciones `user`, la rechazan** con `signatures do not match`. Necesitan un intercambio root único que sustituya el archivo WebView del sistema y borre su entrada `packages.xml`; consulta [el procedimiento TPA10](/es/hardware/panels/tuya/tpa10/#webview-actualiza-esto-primero).
   :::

2. Instálalo manualmente. No necesita root:

   ```sh
   adb install -r android-system-webview.apk
   ```

   Se instala en `/data/app` y sustituye al WebView original obsoleto.

3. Verifica proveedor activo y versión:

   ```sh
   adb shell dumpsys webviewupdate | grep "Current WebView package"
   ```

Si hay varios proveedores, selecciona explícitamente el nuevo:

```sh
adb shell cmd webviewupdate set-webview-implementation com.android.webview
```

o usa Opciones para desarrolladores, _Implementación de WebView_.
