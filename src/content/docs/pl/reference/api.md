Home Assistant służy do automatyzowania i monitorowania panelu. Panel Assistant publikuje każdy panel jako urządzenie z encjami i usługami; jest tam wszystko, czego potrzebuje automatyzacja lub pulpit. Ta strona wymienia encje, własne strony i punkty końcowe panelu oraz stan REST API.

## Encje Home Assistant

Obsługiwane encje pojawiają się w Home Assistant bez YAML. Identyfikatory encji domyślnie mają poniższe postacie, gdzie `<panel>` jest skonfigurowanym identyfikatorem panelu. Encje właściwe dla sprzętu są pomijane, gdy aktywny profil urządzenia deklaruje brak danej możliwości, a opcjonalne encje ustawień i diagnostyki można indywidualnie udostępniać lub ukrywać na stronie Konfiguracja.

| Encja                                                    | Działanie                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `light.<panel>_screen`                                   | Włączanie/wyłączanie ekranu i jasność według schematu JSON światła Home Assistant, z jasnością od `0` do `255`. Wyłączenie zależy od aktywnego profilu: fizyczne wyłączenie podświetlenia tam, gdzie panel je udostępnia, uśpienie Androida przy zweryfikowanej ścieżce `keyevent` albo bezpieczne przyciemnienie jako wariant awaryjny. Na panelu z mikrofonem Home Assistant otrzymuje też encję `assist_satellite.<panel>`: [asystenta głosowego](/pl/manage/voice-assistant/) panelu. Jest niedostępna przy wyłączonym asystencie głosowym.

Encje konfiguracji, wydajności i diagnostyki oparte na rejestrze są publikowane tylko wtedy, gdy udostępniono je na stronie Konfiguracja. Opcjonalne czujniki diagnostyczne to czas ostatniego uruchomienia, użycie CPU, użycie pamięci, temperatura SoC, adres IP, sieć Wi-Fi, siła sygnału Wi-Fi i przerwy Wi-Fi (24 h).

## Automatyzowanie panelu z Home Assistant

Używaj encji panelu i standardowych usług Home Assistant; wywoływanie samego panelu nie jest potrzebne.

- **Odtwarzanie dźwięku lub komunikatu.** Wywołaj `media_player.play_media` na encji odtwarzacza panelu z URL lub źródłem multimediów. Ustaw `announce: true`, aby odczytać komunikat ponad odtwarzanym dźwiękiem. `media_player.media_pause`, `media_player.media_play`, `media_player.media_stop`, `media_player.volume_set` i `media_player.volume_mute` działają jak na każdym odtwarzaczu.
- **Ustawianie głośności.** Na panelu z głośnikiem użyj `media_player.volume_set` na encji odtwarzacza. Panel bez głośnika ma zamiast tego encję liczbową głośności; użyj na niej `number.set_value`.
- **Sterowanie ekranem i pulpitem.** Używaj światła Ekran, encji tekstowej Nawiguj, encji tekstowej Pulpit główny i przycisku ponownego ładowania pulpitu.
- **Monitorowanie panelu.** Obserwuj czujnik stanu i jego atrybuty oraz powyższe czujniki diagnostyczne. Zastępują odpytywanie wiersza stanu skryptem, a Home Assistant przechowuje ich historię.

```yaml
action: media_player.play_media
target:
  entity_id: media_player.wall_panel_media_player
data:
  media_content_type: music
  media_content_id: https://example.com/doorbell.mp3
  announce: true
```

Dźwięk pobierany przez HTTPS korzysta z platformowego magazynu zaufania Androida i weryfikacji nazwy hosta. Certyfikat z podpisem własnym jest odrzucany, chyba że jego CA zainstalowano na panelu; zwykły HTTP pozostaje dostępny dla zaufanych źródeł LAN.

## Własne strony i punkty końcowe panelu

Wybierz **Odwiedź** na stronie urządzenia panelu w Home Assistant, aby otworzyć lokalną stronę panelu. Każdy panel udostępnia mały, stały zestaw ścieżek na swoim porcie HTTP, domyślnie `8888` (np. `http://<panel>:8888/`). Nic więcej nie jest dokumentowane ani obiecywane.

| Ścieżka                      | Przeznaczenie                                                                                                                            |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                          | Stan panelu, możliwości, diagnostyka i bieżący podgląd pulpitu. Jest to `configuration_url` urządzenia Home Assistant.                   |
| `/setup`                     | Prowadzona konfiguracja pierwszego uruchomienia i resetowania: tożsamość, połączenie, renderer, pulpit główny i wybór filtrowania encji. |
| `/configure`                 | Ustawienia renderera i zachowania panelu.                                                                                                |
| `/profiles`                  | Wybór, przeglądanie i tworzenie YAML profili urządzenia.                                                                                 |
| `/entities`                  | Uczenie encji wbudowanego renderera, zasady i nadpisania.                                                                                |
| `/install`                   | Oprogramowanie, kopie zapasowe, przywracanie i konserwacja.                                                                              |
| `/logs`                      | Zanonimizowane bieżące logi aplikacji.                                                                                                   |
| `/health` i `/api/v1/health` | Jednowierszowy raport sprawności opisany poniżej.                                                                                        |
| `/diag` i `/api/v1/diag`     | Raport diagnostyczny w zwykłym tekście. Przejrzyj go przed udostępnieniem.                                                               |
| `/ui`                        | Gniazdo używane przez własne strony panelu. Nie jest interfejsem skryptowym i może się zmieniać między wydaniami.                        |

Strony pobierają też swoje skrypty, style i ikony z panelu.

### Wiersz sprawności

Wiersz sprawności może zawierać `ha=<state>`, gdzie stan to `normal`, `shutting_down`, `starting`, `back_online` lub `connection_lost`. Panel Assistant wysyła natywne powiadomienia cyklu życia; `connection_lost` oznacza zerwanie połączenia bez powiadomienia o zamknięciu i różni się od celowego zamknięcia.

`ha_src=native` oznacza stan cyklu życia zaobserwowany przez Panel Assistant. Stany wywnioskowane lokalnie mogą pomijać ten token. Nie jest używane źródło cyklu życia MQTT.

Gdy panel utrzymuje uwierzytelnione gniazdo Home Assistant z dowolnego powodu (źródło światła otoczenia lub obecności z encji Home Assistant albo obserwowanie rejestru), wiersz sprawności zgłasza też zmierzone połączenie z Home Assistant. Gdy próba ICMP echo otrzyma odpowiedź, `ha_net` i ostrzeżenie panelu korzystają z jej werdyktu z sześciu ostatnich serii, uwzględniającego opóźnienie ścieżki i utratę pakietów. Gdy ta próba jest nieobsługiwana lub nigdy nie otrzymała odpowiedzi, werdykt opiera się na próbach WebSocket z pięciu minut: ponad 5% bez odpowiedzi, przy co najmniej dwóch brakach odpowiedzi, powoduje ostrzeżenie; dwa kolejne braki odpowiedzi powodują stan poważny. Opóźnienie WebSocket w obie strony jest klasyfikowane osobno jako `ha_resp` i nigdy nie podnosi ostrzeżenia panelu. Responsywność WebSocket jest klasyfikowana osobno jako `ha_resp=<healthy|warning|severe>`: ostrzeżenie, gdy ponad 5% odpowiedzi w oknie i co najmniej dwie odpowiedzi przekraczają 250 ms; stan poważny stosuje tę samą regułę przy 1000 ms. To wyłącznie obserwacja wydajności. `ha_net_p95=<ms>` to 95. percentyl metodą najbliższej rangi czasu w obie strony własnych prób ping WebSocket aplikacji (`-1`, gdy żadna próba nie otrzymała odpowiedzi), `ha_net_n=<count>` to liczba prób w oknie, `ha_net_miss=<count>` to próby bez odpowiedzi, a `ha_net_age=<ms>` określa, ile czasu minęło od ostatniej odpowiedzi (`-1`, gdy żadnej nie było). Pozwala to odróżnić gniazdo dopiero połączone od strumienia, który przestał wykonywać próby. Przez pierwsze trzy minuty po starcie aplikacji zgłaszane jest tylko `ha_net=settling`, bez werdyktu, ponieważ obciążenie startowe sprawia, że czas w obie strony opisuje panel, a nie połączenie. Pojedynczy brak odpowiedzi WebSocket lub skok czasu odpowiedzi nigdy nie wywołuje alarmu. Awarie spowodowane przez sam Home Assistant, np. zamknięcie lub odmowa połączenia podczas restartu albo odrzucenie logowania, są liczone osobno, nigdy jako utrata. Próba bez odpowiedzi, podczas gdy nadal przychodzą inne ramki, w tym spóźniona odpowiedź na poprzednią próbę, oznacza zajęty serwer, a nie utraconą ścieżkę: jest liczona jako błąd serwera, a współdzielone gniazdo pozostaje połączone. Pomiar należy do uwierzytelnionego gniazda, a nie do zamiaru połączenia, więc tokeny są nieobecne, dopóki panel rzeczywiście nie połączy się i nie zaloguje, i znikają ponownie po zakończeniu (brak poświadczeń, brak potrzeby gniazda albo połączenie, które zrezygnowało). Gdy wcześniej aktywne gniazdo jest ponownie zestawiane, tokeny pozostają, ponieważ przerwana ścieżka musi być zgłaszana podczas wyjaśnianej przez nią awarii. Poprawny werdykt jest więc zawsze podawany jawnie, a nie przez pominięcie. Raport `/diag` zawiera oba werdykty w jednym wierszu `[ha-network]`; nigdy nie zawiera adresu Home Assistant, nazwy sieci ani pojedynczej próbki. Obok jest drugi niezależny pomiar tej samej ścieżki: panel wysyła krótką serię żądań ICMP echo na adres, z którym rzeczywiście połączone jest jego gniazdo Home Assistant, a `/diag` zawiera wynik w jednym wierszu `[ha-path-probe]`. Ta próba jest okresowa, a nie ciągła; jej odstęp rośnie, gdy ścieżka nadal potwierdza działanie, i wraca do minimum, gdy tylko coś wygląda nieprawidłowo. Zgłasza `state=unsupported`, gdy platforma nie udostępnia aplikacji gniazda ICMP, i `state=unproven`, dopóki echo rzeczywiście nie otrzyma odpowiedzi; wcześniejsza cisza nie jest liczona jako utrata, ponieważ Home Assistant za odwrotnym proxy lub na hoście filtrującym ICMP wyglądałby inaczej jak całkowita awaria sieci przy dobrym łączu. Oba wiersze diagnostyczne podają też **rodzinę adresów, przez którą rzeczywiście połączone jest gniazdo** (`family=ipv4` lub `family=ipv6`), w każdym stanie, także `unsupported`, ponieważ informacja o używanej rodzinie jest najważniejsza przy braku innych dowodów warstwy 3. Nie jest to adres, nazwa hosta ani nazwa sieci.

Strona Konfiguracja może rozpocząć zwykłe logowanie Home Assistant w przeglądarce. Zwrócony odnośnik można otworzyć lub skopiować do prywatnego okna, unikając wpisywania poświadczeń na panelu. Home Assistant przekierowuje do lokalnego punktu zwrotnego panelu; ha-paneld sam wymienia jednorazowy kod i nigdy nie zwraca przeglądarce tokenów dostępu ani odświeżania. Punkt zwrotny jest dostępny tylko przez te same sprawdzenia zaufanej sieci LAN i Host co reszta usługi HTTP panelu, jest związany z adresem panelu, który go uruchomił, wygasa po dziesięciu minutach i wysyła odpowiedzi `no-store`/`no-referrer`.

Usługa celowo używa modelu zaufanej sieci LAN zamiast ogólnego uwierzytelniania. Odrzuca klientów spoza LAN, nieprawidłowe nagłówki Host i żądania przeglądarki z niezgodnym Origin lub Referer przed wyznaczeniem trasy. Utrzymuj usługę HTTP panelu w zaufanej sieci i nie wystawiaj jej bezpośrednio do internetu. Opcjonalny [tryb wzmocniony](/pl/manage/security-mode/) wymaga fizycznego dostępu dla chronionych bezpośrednich żądań LAN; [dokumentacja bezpieczeństwa](/pl/reference/security/) opisuje pełne zasady.

## REST API jest wycofywane

REST API pod `/api/v1` jest przestarzałe, a jego dokumentacja OpenAPI nie jest już publikowana. Panel, który nie udostępnia już ścieżki, odpowiada `410` i `{"error": "gone"}`. REST API przestaje odpowiadać na panelu, gdy Panel Assistant już go nie potrzebuje. Używaj Home Assistant do automatyzacji i monitorowania.

## Parowanie i wykrywanie

ha-paneld ogłasza `_ha-paneld._tcp.local.` z metadanymi wersji, możliwości, trasy i przyjaznej nazwy. Nieprzezroczysty token próby przypisany do respondera pozwala panelowi sprawdzać, czy jego własne bieżące ogłoszenie pozostaje widoczne w LAN; po kolejnych brakach odpowiedzi odbudowuje responder z ograniczonymi ponowieniami, a diagnostyka ostrzega po wyczerpaniu odzyskiwania.
