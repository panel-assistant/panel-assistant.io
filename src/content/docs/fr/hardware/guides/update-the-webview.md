Lisez ceci avant toute chose : un WebView obsolète est la cause la plus fréquente d’échec au premier lancement sur ces panneaux.

Le moteur de rendu intégré de l’application repose sur le **WebView système** d’Android. La plupart de ces panneaux en fournissent un bien trop ancien pour une interface Home Assistant actuelle. Cela peut produire dès l’origine un tableau de bord vide ou défectueux, des cartes manquantes ou « navigateur non pris en charge ». Les panneaux **sans** Google Play (Sonoff NSPanel Pro, Tuya TPA10) nécessitent une autre voie de mise à jour. Les **Electron WF1589T et ZHICAI SMT1019 ont Google Play** : mettez donc à jour _Android System WebView_ depuis le Play Store, ou utilisez le canal de développement Play de WebView.

L’installation et les mises à jour de l’application lancées depuis Home Assistant peuvent aussi installer un WebView compatible vérifié. Cela exige un profil pris en charge, un fournisseur non géré par Play avec le même paquet et le même signataire que la version sélectionnée, et une voie d’installation autorisée. Si cette mise à jour reste inachevée, choisissez **Réessayer** dans la réparation de mise à jour du panneau. Elle vérifie le travail existant avant de demander une nouvelle tentative ; aucune nouvelle tentative n’est programmée. Un ancien moteur n’empêche ni la configuration ni l’association, mais le tableau de bord peut rester impossible à afficher. Le fournisseur d’origine du TPA10, verrouillé par signature, nécessite toujours son remplacement root documenté avant l’utilisation d’un remplacement signé différemment.

## Solution manuelle de repli

Utilisez la méthode existante ci-dessous pour votre panneau lorsque la voie gérée est indisponible. L’installation manuelle directe par adb du WebView Android standard (paquet **`com.android.webview`**) exige une version adaptée à la version Android et à l’ABI du panneau, sans boutique d’applications tierce.

:::tip
Le nom de paquet doit être `com.android.webview` pour que le système le sélectionne automatiquement. Les versions **SystemWebView** de Cromite et LineageOS utilisent `com.android.webview` et s’enregistrent bien comme fournisseur, mais le **navigateur** Cromite ordinaire utilise un autre paquet et ne le fait pas. Utilisez la version SystemWebView, pas l’APK du navigateur.
:::

- **Choisissez le WebView le plus récent pris en charge par la version Android du panneau.** Android 8.1 du NSPanel Pro est limité à Chromium 138, dernier pour Android 8 et 9 ; les versions suivantes ne s’installent pas. Android 10 et ultérieur (le TPA10 utilise 11) exécutent le WebView LineageOS actuel, 150.
- **Les liens directs APKMirror sont des URL présignées de courte durée expirant dans l’heure.** Utilisez la page ou les fichiers de version durables ci-dessus. Le miroir existe parce que ces panneaux n’ont pas Play et fournissent un micrologiciel vieux de plusieurs années ; trouver une version fonctionnelle peut sinon prendre des jours.

:::

## Installer manuellement et vérifier

1. Téléchargez un APK **Android System WebView** récent avec le nom de paquet **`com.android.webview`**. **LineageOS** System WebView est recommandé pour les différentes versions Android : 138 est le dernier pour Android 8.1, et 150 couvre Android 10 et ultérieur ; les deux sont dans le miroir. C’est Chromium standard, sans le blocage de lecture automatique Cromite qui arrête les flux caméra Home Assistant. Son paquet `com.android.webview` assure sa sélection automatique comme fournisseur, sans modifier de liste d’autorisation ni ajouter d’application ; il est librement redistribuable. Respectez l’ABI du panneau.

   :::caution
   L’installation simple ci-dessous fonctionne sur les panneaux dont la ROM dispense du contrôle de signature WebView, comme la version `userdebug` du NSPanel Pro. **Les panneaux verrouillés par signature, dont le TPA10 et probablement d’autres versions fabricant `user`, la refusent** avec `signatures do not match`. Ils nécessitent un remplacement root unique du fichier WebView système et l’effacement de son entrée `packages.xml` ; voir la [procédure TPA10](/fr/hardware/panels/tuya/tpa10/#webview-update-this-first).
   :::

2. Installez-le manuellement. Root n’est pas nécessaire :

   ```sh
   adb install -r android-system-webview.apk
   ```

   Il s’installe dans `/data/app` et remplace le WebView d’origine obsolète.

3. Vérifiez le fournisseur actif et sa version :

   ```sh
   adb shell dumpsys webviewupdate | grep "Current WebView package"
   ```

Si le panneau répertorie plusieurs fournisseurs, sélectionnez explicitement le nouveau :

```sh
adb shell cmd webviewupdate set-webview-implementation com.android.webview
```

ou utilisez les options pour les développeurs, _Implémentation WebView_.
