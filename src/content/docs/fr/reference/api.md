Home Assistant est le moyen d’automatiser et surveiller un panneau. Panel Assistant publie chaque panneau comme appareil avec entités et services ; tout ce dont une automatisation ou un tableau de bord a besoin s’y trouve. Cette page liste les entités, les pages et points d’accès propres au panneau, et le statut de l’API REST.

## Entités Home Assistant

Les entités prises en charge apparaissent dans Home Assistant sans YAML. Leurs identifiants prennent par défaut les formes ci-dessous, où `<panel>` est l’identifiant configuré du panneau. Les entités matérielles sont omises lorsque le profil actif déclare la capacité absente ; les entités facultatives de réglage et diagnostic peuvent être exposées ou masquées individuellement sur la page Configurer.

| Entité                                                   | Contrat                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `light.<panel>_screen`                                   | Allumage/extinction et luminosité selon le schéma JSON de lumière Home Assistant, avec une valeur de `0` à `255`. L’extinction suit le profil actif : coupure physique du rétroéclairage si exposée, veille Android si une voie `keyevent` est validée, ou réduction sûre de luminosité en repli. La voie de veille Android refuse un panneau protégé par code PIN, schéma ou mot de passe. |
| `light.<panel>_led`                                      | LED RGB ou à luminosité seule selon le mécanisme disponible ; les mécanismes compatibles exposent aussi des effets.                                                                                                                                                                                                                                                                         |
| `light.<panel>_buttons`                                  | Rétroéclairage des boutons à luminosité réglable si déclaré par le profil actif.                                                                                                                                                                                                                                                                                                            |
| `light.<panel>_button_led1` à `button_led4`              | LED de boutons commandées individuellement si déclarées par le profil actif.                                                                                                                                                                                                                                                                                                                |
| `switch.<panel>_relay1` à `relay4`                       | Relais matériels si déclarés par le profil actif.                                                                                                                                                                                                                                                                                                                                           |
| `text.<panel>_navigate`                                  | Envoie un chemin de tableau de bord au moteur actif. Le moteur intégré navigue dans son processus ; un moteur externe reçoit un lien profond.                                                                                                                                                                                                                                               |
| `text.<panel>_home_dashboard`                            | Configure le chemin utilisé par les actions de retour au tableau de bord.                                                                                                                                                                                                                                                                                                                   |
| `number.<panel>_volume`                                  | Volume d’annonce de `0` à `100` pour cent sur le flux musical Android, uniquement sur un panneau sans haut-parleur. Un panneau avec haut-parleur règle plutôt son volume via son lecteur multimédia.                                                                                                                                                                                        |
| `event.<panel>_button`                                   | Événements des boutons matériels, publiés si la capture d’accessibilité Android est activée ou si le profil actif déclare une voie de boutons vérifiée.                                                                                                                                                                                                                                     |
| `sensor.<panel>_illuminance`                             | Éclairement ambiant en lux si le panneau possède un capteur de lumière Android standard.                                                                                                                                                                                                                                                                                                    |
| `sensor.<panel>_temperature` / `sensor.<panel>_humidity` | Mesures climatiques du panneau si déclarées par le profil actif.                                                                                                                                                                                                                                                                                                                            |
| `binary_sensor.<panel>_proximity`                        | État d’occupation proche/loin étalonné. Reste indisponible tant que le modèle local n’est pas fiable.                                                                                                                                                                                                                                                                                       |
| `sensor.<panel>_proximity_level`                         | Proximité normalisée de `0` pour la référence lointaine étalonnée à `100` pour la référence proche étalonnée.                                                                                                                                                                                                                                                                               |
| `sensor.<panel>_zigbee_gateway_health`                   | Santé bornée de la passerelle et attributs diagnostiques expurgés sur les panneaux Zigbee.                                                                                                                                                                                                                                                                                                  |
| `sensor.<panel>_storage_health`                          | Diagnostic du stockage et de SQLite avec attributs d’espace libre, croissance de base et intégrité bornée. Une pression critique ou une défaillance de base fait aussi échouer la vérification de l’installateur ; ha-paneld ne libère pas automatiquement d’espace.                                                                                                                        |
| `camera.<panel>_camera`                                  | Vue en direct et images fixes de la caméra via son flux RTSP. Désactivée par défaut. Son activation via l’entité Home Assistant exige une approbation sur le panneau dans tous les modes de sécurité ; sa désactivation n’en exige pas. L’autorisation caméra Android et un indicateur fonctionnel d’utilisation sont aussi nécessaires.                                                    |
| `button.<panel>_reload`                                  | Recharge le moteur intégré dans son processus ou redémarre le moteur externe sélectionné.                                                                                                                                                                                                                                                                                                   |
| `button.<panel>_reboot`                                  | Redémarre via une voie privilégiée disponible.                                                                                                                                                                                                                                                                                                                                              |
| `media_player.<panel>_media_player`                      | Haut-parleur du panneau : lire une URL ou source multimédia, annoncer par-dessus la lecture, mettre en pause, reprendre, arrêter, régler ou couper le volume.                                                                                                                                                                                                                               |
| `sensor.<panel>_status`                                  | Indique si le panneau est `online`, `connected` (il garde sa session mais son adresse enregistrée ne répond pas), en redémarrage pour `update`, `settings`, `recovery` ou `reboot`, ou authentifié auprès d’un autre Home Assistant. Ses attributs contiennent `reachable`, `connected`, `build`, `config_hash` et `home_assistant_state`.                                                  |

Sur un panneau avec microphone, Home Assistant reçoit aussi une entité `assist_satellite.<panel>` : l’[assistant vocal](/fr/manage/voice-assistant/) du panneau. Elle est indisponible lorsque l’assistant est désactivé.

Les entités de configuration, performances et diagnostic fondées sur le registre ne sont publiées que si exposées sur Configurer. Les capteurs diagnostiques facultatifs sont Heure du dernier démarrage, Utilisation du CPU, Utilisation de la mémoire, Température du SoC, Adresse IP, Réseau Wi-Fi, Puissance du signal Wi-Fi et Coupures Wi-Fi (24 h).

## Automatiser un panneau depuis Home Assistant

Utilisez les entités et services Home Assistant standard ; aucun appel au panneau lui-même n’est nécessaire.

- **Lire de l’audio ou annoncer.** Appelez `media_player.play_media` sur l’entité Lecteur multimédia du panneau avec une URL ou source multimédia. Définissez `announce: true` pour parler par-dessus la lecture en cours. `media_player.media_pause`, `media_player.media_play`, `media_player.media_stop`, `media_player.volume_set` et `media_player.volume_mute` fonctionnent comme sur tout lecteur multimédia.
- **Régler le volume.** Avec un haut-parleur, utilisez `media_player.volume_set` sur l’entité Lecteur multimédia. Un panneau sans haut-parleur possède plutôt le nombre Volume ; utilisez `number.set_value`.
- **Commander écran et tableau de bord.** Utilisez la lumière Écran, l’entité texte Naviguer, l’entité texte Tableau de bord d’accueil et le bouton Recharger le tableau de bord.
- **Surveiller un panneau.** Observez le capteur État et ses attributs, ainsi que les capteurs ci-dessus. Ils remplacent l’interrogation de la ligne de santé par script, et Home Assistant conserve leur historique.

```yaml
action: media_player.play_media
target:
  entity_id: media_player.wall_panel_media_player
data:
  media_content_type: music
  media_content_id: https://example.com/doorbell.mp3
  announce: true
```

L’audio récupéré par HTTPS utilise le magasin de confiance Android et la vérification du nom d’hôte. Un certificat autosigné est refusé sauf si son autorité est installée sur le panneau ; HTTP simple reste disponible pour les sources LAN fiables.

## Pages et points d’accès propres au panneau

Sélectionnez **Visiter** sur sa page d’appareil Home Assistant pour ouvrir sa page locale. Chaque panneau sert un petit ensemble fixe de chemins sur son port HTTP, `8888` par défaut (par exemple `http://<panel>:8888/`). Rien d’autre n’est documenté ni garanti.

| Chemin                        | Fonction                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `/`                           | État, capacités, diagnostics et aperçu du tableau de bord. C’est la `configuration_url` de l’appareil Home Assistant.          |
| `/setup`                      | Parcours guidé initial et de réinitialisation pour identité, connexion, moteur, tableau de bord d’accueil et filtre d’entités. |
| `/configure`                  | Réglages du moteur et du comportement du panneau.                                                                              |
| `/profiles`                   | Sélection, inspection et création YAML de profils d’appareil.                                                                  |
| `/entities`                   | Apprentissage des entités, politique et dérogations du moteur intégré.                                                         |
| `/install`                    | Logiciels, sauvegarde, restauration et maintenance.                                                                            |
| `/logs`                       | Journaux applicatifs en direct expurgés.                                                                                       |
| `/health` et `/api/v1/health` | Rapport de santé sur une ligne décrit ci-dessous.                                                                              |
| `/diag` et `/api/v1/diag`     | Rapport de diagnostic en texte brut. Relisez-le avant de partager.                                                             |
| `/ui`                         | Socket utilisé par les pages du panneau. Ce n’est pas une interface de script et il peut changer entre versions.               |

Les pages chargent aussi scripts, styles et icônes depuis le panneau.

### La ligne de santé

Elle peut contenir `ha=<state>`, où l’état est `normal`, `shutting_down`, `starting`, `back_online` ou `connection_lost`. Panel Assistant envoie des avis natifs de cycle de vie ; `connection_lost` signifie une perte de connexion sans avis d’arrêt et se distingue d’un arrêt volontaire.

`ha_src=native` identifie un état observé via Panel Assistant. Les états déduits localement peuvent omettre ce jeton. Aucune source MQTT de cycle de vie n’est utilisée.

Tant que le panneau garde un socket Home Assistant authentifié, quelle qu’en soit la raison (source d’entité de lumière ambiante ou de présence Home Assistant, ou surveillance du registre), la ligne rapporte aussi la connexion mesurée. `ha_net=<healthy|warning|severe>` est le verdict glissant sur cinq minutes du **chemin réseau** : avertissement si plus de 5 % des sondes restent sans réponse, grave si deux sondes consécutives restent sans réponse. La latence aller-retour ne l’élève jamais : elle inclut le temps de réponse Home Assistant et l’ordonnancement des fils du panneau ; sur un panneau filaire, elle peut indiquer des centaines de millisecondes pour un chemin réel inférieur à deux. Elle est classée séparément par `ha_resp=<healthy|warning|severe>`, au-delà de 100 ms pour un avertissement et 1 000 ms pour grave, et n’est qu’une observation de performances. `ha_net_p95=<ms>` est le 95e centile au rang le plus proche de l’aller-retour des propres sondes ping WebSocket de l’application (`-1` tant qu’aucune n’a répondu), `ha_net_n=<count>` le nombre de sondes de la fenêtre, `ha_net_miss=<count>` les sondes sans réponse et `ha_net_age=<ms>` le délai depuis la dernière réponse (`-1` si aucune), distinguant un socket tout juste connecté d’un flux ayant cessé de sonder. Durant les trois premières minutes après démarrage, seul `ha_net=settling` est rapporté, sans verdict : la charge initiale fait décrire par l’aller-retour le panneau plutôt que la connexion. Un échec ou pic isolé ne déclenche jamais d’alarme. Les échecs causés par Home Assistant, comme la fermeture ou le refus de connexion pendant son redémarrage ou le rejet de connexion au compte, sont comptés à part, jamais comme pertes. Une sonde sans réponse alors que d’autres trames continuent d’arriver, y compris une réponse tardive à une sonde précédente, indique un serveur occupé plutôt qu’un chemin perdu : elle compte comme défaillance serveur et le socket partagé reste ouvert. La mesure appartient à un socket authentifié, pas au souhait d’en avoir un : les jetons sont absents tant que le panneau n’est pas réellement connecté et authentifié, puis à nouveau après son arrêt (aucun identifiant, aucun besoin du socket ou connexion abandonnée). Pendant le rétablissement d’un socket auparavant actif, les jetons restent présents, car un chemin défaillant doit être signalé pendant la panne qu’il explique. Un verdict sain est donc toujours explicite plutôt qu’implicite par omission. Le rapport `/diag` porte les deux verdicts sur une ligne `[ha-network]` ; il n’inclut jamais l’adresse Home Assistant, le nom du réseau ou un échantillon individuel. Une seconde mesure indépendante du même chemin apparaît à côté : le panneau envoie une petite rafale de requêtes d’écho ICMP à l’adresse réellement utilisée par son socket Home Assistant, et `/diag` donne le résultat sur une ligne `[ha-path-probe]`. Cette sonde est intermittente, pas continue ; son intervalle s’élargit à mesure que le chemin fait ses preuves et revient au minimum dès qu’un problème apparaît. Elle indique `state=unsupported` si la plateforme refuse un socket ICMP à l’application, et `state=unproven` avant la première réponse réelle ; le silence préalable ne compte pas comme perte, sinon un Home Assistant derrière un proxy inverse ou un hôte filtrant ICMP semblerait avoir un réseau totalement défaillant malgré une bonne liaison. Cette sonde est uniquement rapportée ; elle n’élève pas l’avertissement du panneau. Les deux lignes indiquent aussi la **famille d’adresses réellement utilisée par le socket** (`family=ipv4` ou `family=ipv6`), dans tous les états y compris `unsupported`, car cette information compte particulièrement sans autre preuve de couche 3. Ce n’est ni une adresse, ni un nom d’hôte, ni un nom de réseau.

La page Configurer peut démarrer la connexion habituelle par navigateur Home Assistant. Le lien renvoyé peut être ouvert ou copié dans une fenêtre privée, évitant de saisir des identifiants sur le panneau. Home Assistant redirige vers le rappel local au panneau ; ha-paneld échange lui-même le code à usage unique et ne renvoie jamais de jeton d’accès ou d’actualisation au navigateur. Le rappel subit les mêmes contrôles LAN fiable et Host que le reste du service HTTP, est lié à l’adresse du panneau qui l’a démarré, expire après dix minutes et envoie des réponses `no-store`/`no-referrer`.

Le service utilise volontairement un modèle LAN de confiance plutôt qu’une authentification générale. Il refuse avant routage les pairs hors LAN, les en-têtes Host invalides et les requêtes navigateur dont Origin ou Referer ne correspond pas. Gardez le service HTTP du panneau sur un réseau fiable et ne l’exposez pas directement à Internet. Le [mode renforcé](/fr/manage/security-mode/) facultatif exige un accès physique pour les requêtes LAN directes protégées ; la [référence de sécurité](/fr/reference/security/) décrit l’ensemble de la posture.

<a id="the-rest-api-is-deprecated"></a>

## L’API REST est obsolète

L’API REST sous `/api/v1` est obsolète et sa référence OpenAPI n’est plus publiée. Un panneau ne servant plus un chemin répond `410` et `{"error": "gone"}`. L’API REST cesse de répondre sur un panneau dès que Panel Assistant n’en a plus besoin. Utilisez Home Assistant pour automatisations et surveillance.

## Association et découverte

ha-paneld annonce `_ha-paneld._tcp.local.` avec métadonnées de version, capacités, routes et nom convivial. Un jeton de sonde opaque par répondeur permet au panneau de vérifier que son annonce actuelle reste visible sur le LAN ; après des échecs répétés, il reconstruit le répondeur avec des tentatives bornées, et les diagnostics avertissent si la récupération est épuisée.
