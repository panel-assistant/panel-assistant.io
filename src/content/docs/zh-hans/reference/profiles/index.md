面板配置文件描述某个 Android 墙面板型号的特性：ha-paneld 如何识别它、它可使用哪些已编译硬件驱动、已知的显示和传感器特征，以及取决于固件的变体。配置文件是可读的 YAML 文件。无需重新构建 Android 应用，就能在运行中的 ha-paneld 安装中查看、导出、编辑、导入和激活它们。

本页是实用编写指南。文档模型请参阅[格式与兼容性参考](/zh-hans/reference/profiles/format/)；激活硬件控制前，请阅读[测试与故障排查](/zh-hans/reference/profiles/testing/)；发布配置文件前，请阅读[共享与贡献指南](/zh-hans/reference/profiles/sharing/)。另有明确分开的[社区配置文件](/zh-hans/reference/profiles/community/)目录；这些文件需手动导入，不代表内置支持。

应用内置的配置文件位于 ha-paneld 仓库的 [`app/src/main/assets/device-profiles`](https://github.com/panel-assistant/android/tree/main/app/src/main/assets/device-profiles)。

![面板配置文件页面的编辑器显示内置修订的 YAML，标有软件包停用建议、root 路径和 WebView 安装包元数据的审阅徽章，下方显示观察到的设备事实](/screenshots/ui-profile-dark.png)

## 配置文件能做什么

配置文件可选择 ha-paneld 已提供的驱动和转换，并提供其有类型的参数。它可描述硬件事实、匹配规则、固件变体、显示建议、候选能力，以及面板上可能有用的 Android 权限级别。

配置文件不能增加可执行代码、shell 命令、辅助守护进程动词、内核 ioctl、原生库或新硬件协议。如果面板需要配置文件编辑器或格式参考中未列出的机制，必须先在 ha-paneld 本身实现并审阅该机制。此边界让交换的 YAML 文件可供检查，防止配置文件变成任意 root 脚本。

配置文件也不授予权限。所需实时途径未成功前，特权驱动仍不可用。请参阅[权限：标准 Android 与特权途径](#权限标准-android-与特权途径)。

## 无需开发环境的快速入门

只需支持配置文件的 ha-paneld 安装和 Web 浏览器。配置文件页面包含带验证反馈的 YAML 编辑器；可选用导出到独立文本编辑器的方式。无需 Android Studio、Gradle、Android SDK 或仓库检出。

1. 在 Home Assistant 打开面板设备页面，选择**访问**，然后打开**配置文件**。直接连接时，使用面板报告的 HTTP 端口（默认端口为 `http://<panel-ip>:8888/profiles`）。
2. 如果 ha-paneld 已识别面板，请导出准确的当前配置文件修订作为参考。内置配置文件不可变，因此首次编辑会创建独立的本地分支，而不会更改应用附带的副本。
3. 如果面板使用 **Generic**，请下载其被动设备草稿。草稿包含面板指纹和明确的未知/TODO 值；不会猜测特权硬件或运行主动探测。
4. 为配置文件指定稳定的小写 ID 和版本，补全来源和兼容性元数据，并从精确匹配规则开始。使用[下方示例](#示例)和[格式参考](/zh-hans/reference/profiles/format/)。
5. 在配置文件页面导入 YAML。导入和验证仅为预览：不会保存或激活任何内容。
6. 阅读每条验证消息，并将候选配置文件与当前配置文件比较。特别注意指纹匹配、驱动、硬件路径、新增或移除的 Home Assistant 实体，以及权限要求。
7. 保存通过验证的候选配置文件。保存会创建不可变、未激活的本地修订，仍不会更改运行中的面板。
8. 按照[测试检查表](/zh-hans/reference/profiles/testing/)分阶段测试。如果配置文件改变屏幕、输入、LED、继电器、软件包或其他特权行为，只有有人能看到并接触面板时才激活。
9. 激活需要明确确认，并绑定到准确的配置文件 ID、修订和内容哈希。ha-paneld 会重启服务，让所有控制器接收相同的解析后配置文件。
10. 重启后，确认配置文件页面将预期修订报告为**已激活**，检查能力和 Home Assistant 实体，并测试回退。如果启动验证失败，ha-paneld 会返回**上一个已知可用**修订，并将失败候选报告为**已自动回退**。

请保留导出的 YAML 作为可交换的源文件。绿色配置文件页面的截图是有用证据，但不能替代文件、来源信息或分阶段硬件测试结果。

## 示例

[`minimal-community.yaml`](https://github.com/panel-assistant/android/blob/main/docs/profiles/examples/minimal-community.yaml) 示例使用配置文件页面接受的公共模式。它是教学材料，不代表虚构硬件实际存在。它是保守的标准 Android 起点，不启用厂商协议、root/辅助进程路径、继电器、evdev 输入、更新安装包、软件包目标状态或配置流程。

通过**配置文件**导入示例，检查验证预览，只保存为未激活的本地修订。在用它作为真实面板的基础前，更改 ID、来源、精确指纹、已测试固件和限制。导入后的匹配仅为预览证据；本地和社区配置文件永远不会自动选中。

完整生产示例可从运行中的面板导出不可变的内置配置文件，或阅读[内置 YAML 文件](https://github.com/panel-assistant/android/tree/main/app/src/main/assets/device-profiles)。这些配置文件使用相同模式，但可能选择特权编译驱动和核心拥有的安装包，没有硬件证据时不应照搬。

## 配置文件生命周期

ha-paneld 将配置文件内容视为不可变修订，而非可实时编辑的设置对象。这使比较可重现，并防止更改后的上传内容在早先预览下被激活。

- **内置**：随 ha-paneld 提供且不可变。可导出或创建分支。
- **本地未激活修订**：在此面板导入或创建，已验证并保存，但运行中的控制器不使用它。
- **待处理**：准确修订已接受激活，服务正在重启。
- **已激活**：用于构建当前传感器、硬件控制器、界面能力模型和 Home Assistant 发现信息的修订。
- **上一个已知可用**：新修订完成启动后，保留先前已验证选择，作为恢复和手动回退目标。
- **已自动回退**：激活失败并被上一个已知可用修订自动替换的候选。

保存、激活和删除都使用修订哈希和代次检查。如果页面打开后，另一个浏览器或管理员更改了目录，过期操作会被拒绝；请刷新、重新比较，再根据新状态操作。

删除未激活的本地修订不会更改当前面板。在存在其他有效恢复途径前，不得移除已激活或上一个已知可用修订。

**使用自动匹配**会在下次受控重启时，让固定选择配置文件的面板恢复内置指纹匹配。导入和社区修订永远不参与自动选择；它们仅能通过明确的固定激活使用。

## 从 Generic 开始

`Generic` 是未识别面板的保守备用配置。它使用普通 Android 能力检查和安全运行时探测，但有意不臆造厂商硬件、evdev 按钮、继电器、无线模块、温湿度芯片、更新安装包或软件包操作。

因此 Generic 适合作为社区配置文件的起点：

1. 从配置文件页面下载**设备草稿**。它记录 ha-paneld 可获得的准确构建型号、构建设备和产品版本证据，以及最新的有限、已清理被动报告。
2. 分享前脱敏并审阅。生成报告面向支持用途，但作者仍负责移除面板名称、地址、Home Assistant 详情、凭据和仪表盘内容。
3. 先添加身份和来源。使用带作者/组织前缀的稳定小写 ID，例如 `org.example.wallpanel-x1`，再提供初始配置文件版本、作者/来源/许可证信息、成熟度、已测试固件范围和已知限制。
4. 添加范围狭窄的精确指纹规则。厂商型号或产品版本前缀通常比 `px30`、`rk3326`、`rk3566` 或 `rk3576` 等宽泛 SoC 别名更安全，因为无关面板可能共用这些别名。
5. 未知能力章节应省略或明确标为未知。文件名、零售商品信息或固件编译的内核驱动，不能证明实机硬件存在或 Android 应用可访问它。
6. 每次只添加一项有证据的能力，先验证、比较和测试，再继续。

草稿有意保持只读和被动。不要把探索性 shell 命令或一次性 root 实验变为配置文件字段。确实需要新主动探测或驱动时，应提出有明确边界的 ha-paneld 实现，并有独立验证和测试。

## 安全匹配面板

匹配是安全决策。错误匹配可能选择不合适的驱动，或声明属于使用相同参考主板的另一产品的能力。

按以下顺序优先采用精确产品身份：

1. 产品独有的厂商型号或设备代号；
2. 精确产品版本格式或严格锚定的前缀；
3. 独立构建字段的组合；
4. 仅在有意提供兼容备用时使用宽泛 SoC/参考平台别名。

为每个精确组分配高于其宽泛备用组的分支优先级。ha-paneld 先比较匹配组优先级，再比较配置文件级优先级；内置精确匹配平局时默认退回 Generic。优先级用于重现有意安排的分支顺序，不能替代范围狭窄的指纹。

社区和导入修订永远不参与自动选择，即使精确匹配也是如此。匹配是帮助管理员判断文件是否描述此面板的预览证据。本地修订只能通过明确激活覆盖内置检测，之后面板固定其准确配置文件 ID、修订和哈希。因此后续导入不能隐式更改运行结果。

对于同一硬件系列内受支持的差异，例如产品标签或密度规则，请使用核心拥有的具名策略字段。格式不包含通用表达式语言或任意变体补丁。接近感应的比例、极性和二值/距离行为有意不作为配置文件策略：运行时会从实机证据学习。如果现有具名策略无法描述真实的采集、驱动、权限边界或恢复差异，请使用单独配置文件。

## 权限：标准 Android 与特权途径

配置文件描述候选机制；实时探测决定运行中的面板能否使用它们。

### 标准 Android

从这里开始。仪表盘渲染、Panel Assistant 配对以及普通 Android 传感器、亮度、音频、导航和本地 Web 界面都不需要 root。新配置文件应先证明身份和标准 Android 行为，再添加特权驱动。

### 厂商 root 或 ha-paneld 辅助进程

已编译驱动可能需要可用的厂商 `su` 途径或单独安装的 ha-paneld root 辅助进程。声明该要求不会创建途径、安装辅助进程或扩大其允许列表。辅助进程只接受已编译、有边界的命令，并验证对端身份；配置文件向命令提供已验证参数，绝不提供命令文本。

不要仅为满足配置文件而建议为出厂未 root 的设备取得 root。请如实记录减少的功能集。硬件方面请参阅 [Root 访问](/zh-hans/hardware/guides/root-access/)。

## 更新已安装的配置文件

配置文件内容版本和文档模式版本解决不同问题。硬件知识或行为改变时，递增配置文件版本。只有 ha-paneld 改变文档语言时才改变模式版本。

保存更新前，与当前修订比较并阅读兼容性报告。ha-paneld 更新也会在使用前重新验证已安装配置文件。需要更新核心、不可用驱动或不受支持的未来模式的文件会保持安装，但无法激活；当前上一个已知可用配置文件继续运行。

即使 YAML 差异很小，也应将匹配、特权驱动、路径、固件变体、软件包目标状态、流程选择或核心拥有的更新安装包变更视为重要行为变化。重新执行相关测试阶段，并递增配置文件版本。
