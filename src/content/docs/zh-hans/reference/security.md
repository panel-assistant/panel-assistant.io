ha-paneld 在墙面板上运行前台代理，提供本地 Web 服务（默认端口 `8888`）、root 辅助守护进程，以及按需启用的 CDP/DevTools 中继。**宽松模式默认保留开箱即用的局域网信任和无令牌配对。** 可选的[加固模式](/zh-hans/manage/security-mode/)要求对受保护的直接局域网请求现场接触面板。管理员可以通过已认证的 Panel Assistant 侧边栏执行部分日常管理操作；其他受保护操作仍需在面板屏幕上批准。侧边栏不会代理面板 Web 界面：它显示面板自身页面，并通过面板已认证的 Home Assistant 会话转发该页面请求，由此识别管理员，因此没有单独的集成凭据。其余未经身份验证的本地服务属于已接受的残余风险，网络隔离是更广泛的控制措施；如果增加通用身份验证，将采用 Home Assistant 的身份验证模型。本页记录威胁模型和已作出的决策。

## 信任模型

面板和 Home Assistant 通常位于**可信局域网**，应用围绕**开箱即用、无需令牌的配对体验**构建。已取得面板 root 或文件级访问的攻击者不在范围内（他们已控制设备）。对于加固模式的边界，面板上已运行的软件也受信任，因为无法可靠地将回环请求归属于 ha-paneld 界面而非另一 Android 本地应用。加固模式是可选的现场操作边界，适用于不应允许所有远程客户端执行破坏性或携带凭据操作的网络；它不是完整的身份验证层。

:::caution
值得关注的**已接受残余风险**：没有凭据的局域网参与者仍可访问未经身份验证的本地 HTTP 路径。加固模式保护[安全模式页面](/zh-hans/manage/security-mode/)列出的操作，并对已认证管理员侧边栏提供有限例外，但并不验证每次读取或日常控制。限制访问范围仍由网络隔离负责（[决策 2](#决策)），通用身份验证将采用 Home Assistant 身份验证（[决策 3](#决策)）。
:::

风险主要集中在面板 HTTP 端口上会更改状态的路径：

- 加固模式下，更改 Home Assistant 来源后不能继承先前端点存储的凭据：必须在同一次保存中提供替代凭据，否则旧凭据会清除。凭据清除适用于两种安全模式。由于日常配置通常不需要批准，重新指向其他地址仍有拒绝服务风险。
- 远程媒体播放会下载并播放任意 HTTP(S) URL；HTTPS 使用平台信任存储和正常主机名验证，局域网来源仍可使用明文 HTTP。加固模式下远程媒体请求需要现场批准。
- 宽松模式下，启动 DevTools 中继会启动 CDP 中继（上述 `:9222` 攻击面）；加固模式会关闭并禁用它，而不是批准它。
- 配置文件保存/激活/回退路径可在受控服务重启后改变面板使用的已编译硬件驱动和候选能力。预览令牌将保存操作绑定到准确检查过的 YAML，激活固定准确的修订/哈希，突出显示风险声明，启动时会回退到上一个已知可用修订。加固模式下，激活和回退需要现场批准。
- `GET /diag` 返回设备和能力信息（有助于侦察）。它有意作为支持工具提供。
- 截图和输入注入可查看面板并注入输入。root/辅助进程途径已提供这些能力；本地启用的无障碍服务还可无需 root 提供点击，以及 Android 11 及以上的截图。加固模式保留截图，但拒绝非回环输入，使远程调用方无法操作原生批准界面。
- 组件安装可安装固定签名者的 ha-paneld 或精简 Home Assistant 移动应用构建。组件安装和已检查上传 APK 的提交操作受加固模式保护。
- 完整备份导出与恢复路径可携带配置秘密；在有 root 或辅助进程的面板上明确选择时，还可包含允许列表内的 Home Assistant 移动应用登录文件。加固模式的批准保护网络导出与恢复；推荐使用加密 `.hpb` 归档作为便携格式。辅助进程没有通用私有文件系统命令，移动应用登录迁移受到描述符约束、大小限制，并以事务方式恢复。

管理服务在可信局域网模型下使用明文 HTTP。受保护请求和敏感数据需要可信且隔离的网络；加固模式不会加密传输。

### 经浏览器发起的攻击

经浏览器发起的攻击由 [`OriginGuard`](https://github.com/panel-assistant/android/blob/main/app/src/main/kotlin/io/panelassistant/android/http/OriginGuard.kt) 防护：

- **CSRF**：对于更改状态的请求（`POST`/`PUT`/`PATCH`/`DELETE`），如果存在 `Origin`/`Referer` 但与请求 `Host` 不匹配，OriginGuard 会拒绝，防止恶意局域网网页悄然操作端点。同源界面的 `fetch` 和不带这些标头的 API 客户端（curl、Home Assistant `rest_command`）不受影响。
- **DNS 重绑定**：`Host` 标头必须是 IP 字面值、`localhost`、`*.local`（mDNS）或操作员配置的名称（`http_allowed_hosts`）；其他主机名对所有方法均被拒绝，因此将自有 DNS 名称重绑定到面板的攻击者无法冒充同源读取秘密（配置导出）或操作这些接口。通常使用的 IP 地址访问始终允许，且天然不受重绑定影响。

每个请求先通过重绑定检查；之后的处理取决于它是否更改状态、启动特权工作或仅为普通读取：

1. **Host 检查。** 没有 `Host` 标头的请求通过，因为没有可重绑定的名称。存在 `Host` 时，必须是 IP 字面值、`localhost`、`*.local` 或列于 `http_allowed_hosts`，否则拒绝请求。
2. **更改状态的方法**（`POST`、`PUT`、`PATCH`、`DELETE`）。没有 `Origin` 或 `Referer` 时，按无标头局域网 API 客户端允许。存在其中之一时，必须可解析，且其 authority 必须等于 `Host`；否则按跨源写入拒绝。
3. **主动 `GET`**（启动采集、子进程、采样或网络刷新）。`Sec-Fetch-Site` 为 `cross-site` 或 `same-site` 时拒绝。否则，存在的 `Origin` 或 `Referer` 要经过与写入相同的解析和匹配检查。两者都不存在时，如果用户代理看似浏览器却不带 Fetch Metadata，则拒绝；其他请求按自动化允许。
4. **普通 `GET`** 允许，因为浏览器同源策略已阻止跨源读取响应。

其中有三种行为容易被误解。**缺少 `Host` 的请求会通过**重绑定检查。带有 `Origin` 或 `Referer` 但没有 `Host` 的状态更改请求会被拒绝，所提供的来源无法解析的请求也会被拒绝。这些防护仍允许不带这两个来源标头中任何一个的请求。普通 `GET` 请求刻意不受来源防护；需要防护的是写入或主动读取产生的_副作用_。而主动 `GET` 请求采用基于 Fetch Metadata 的第三条处理路径：对于看起来来自浏览器、却未提供明确同源证据的请求，默认拒绝，同时让不带标头的自动化请求仍能正常工作。

两项防护都不验证_调用方_身份。加固模式可要求受保护操作取得现场批准；决策 3 说明通用调用方身份验证的途径。

通过 [`AppInstaller`](https://github.com/panel-assistant/android/blob/main/app/src/main/kotlin/io/panelassistant/android/util/AppInstaller.kt) 下载 APK 安装包时仅允许 HTTPS：初始 URL 和每次重定向都必须为 `https`。这是下载后签名者和包名固定检查之外的纵深防御；后者已阻止安装被替换的 APK。

运行时配置文件被视为不可信数据，而非插件。封闭模式只能选择编译进 ha-paneld 的驱动，不包含 shell 命令、辅助进程动词、原生代码或通用脚本。特权路径受核心允许列表限制；WebView 安装包元数据只能选择核心拥有的 ID，其 HTTPS URL、版本、安装包校验和及签名者哈希均编译在应用中。用户主动启动的更新只会在已安装提供程序、签名者、Android 版本、ABI 和安装途径兼容时使用这些已验证安装包。安全敏感的驱动参数由所属驱动验证，声明永远不能替代实时 root/辅助进程或硬件探测。

## 决策

1. **不使用自定义 API 令牌。** 每面板秘密容易被丢弃，且破坏简易设置。（已否决。）
2. **不在应用内设置网络允许列表。** 限制_谁_能访问面板 HTTP 端口交由网络层（路由器、VLAN 或防火墙隔离）负责，而非在应用中重新实现，这与依靠现有平台和基础设施能力的原则一致。Home Assistant 自身的 IP 允许列表和 `ip_ban` 保护其 HTTP 服务器，不保护面板独立的 HTTP 服务，因此不适用于此处；现有控制措施是网络隔离。需要应用内方案时，将采用 Home Assistant 身份验证模型（决策 3）。
3. **不做通用调用方身份验证。** 面板应用不验证本地网络调用方身份；控制措施是上述信任模型和加固模式。
4. **静态凭据加密不在范围内。** 已取得面板 root 或文件级访问的攻击者已控制设备。
5. **媒体播放保留标准 HTTPS 验证，同时允许明文 HTTP**，用于局域网信任模型下的局域网音频来源。
6. **加固模式为可选且仅限本机。** 宽松模式仍为默认，使 Home Assistant 工作流和管理多面板的工具不会出现无人处理的提示。加固批准仅在当前进程有效，绑定到 HTTP 对端和准确的受保护请求，有效期十分钟，并由一次匹配重试消耗。它不能由网络请求、备份、恢复或跨多面板操作启用，也不能与传统 TCP ADB、持久或明确指定地址的 ADB 监听器、Android 无线调试或局域网 WebView 开发工具中继共存。只有验证这些远程控制路径均未运行后才能进入，否则默认拒绝。启用时，非回环点击注入不可用。面板上已运行的回环软件仍受信任。加固模式涵盖携带凭据的导出与恢复、软件和软件包更改（包括绑定到一个准确 URL 的下载）、配置文件激活、重启、显示与渲染器维护、数据库恢复维护及远程媒体。在两种模式下，通过 Home Assistant 实体启用摄像头都需要面板批准；设置页面是独立的所有者设置途径。

:::note
有关各平台如何组织设备专用 su 调用点和辅助守护进程路径，请参阅[设备配置文件架构](/zh-hans/reference/profiles/architecture/)。
:::
