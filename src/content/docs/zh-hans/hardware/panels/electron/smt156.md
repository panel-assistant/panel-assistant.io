## 面板应用支持

内置 [`zx-smt156.yaml`](https://github.com/panel-assistant/android/blob/main/app/src/main/assets/device-profiles/zx-smt156.yaml) 配置文件提供正确身份，并明确选择可用的 `/dev/ledjni` RGB 控制器。在报告者提供测得响应前，使用保守的 LED 传递曲线。标准 Android 亮度、光与接近感应、导航、Home Assistant 实体和内置仪表盘无需 root 即可工作。

配置文件将室内温度和室内湿度作为可选附加功能，而非核心支持。报告者证据显示，`sun-ths` 在 `ABS_THROTTLE` 上提供以百分之一摄氏度为单位的温度，`sun-hum` 在厂商轴 `0x1d` 上提供以百分之一百分比为单位的相对湿度。面板应用通过允许列表内的 root 辅助进程读取这些节点。辅助进程不可用时，不发布室内温湿度读数。由于面板自身发热特性尚未测定，提供本地温度校准偏移。

报告的安装没有应用可访问的 `su`，但 USB `adb root`、厂商工程模式和持久解锁途径尚未测定，并非已排除。运行时探测决定哪些途径存在，每次使用特权途径时都会检查。在确认某一途径前，重启和仅 root 控制需要已安装的辅助进程；屏幕关闭会将亮度设为零，因为配置文件没有声明关闭背光途径；核心 ZX-SMT156 支持不需要这些仅 root 控制。配置文件有意不声明继电器路径，因为根据厂商 MQTT 功能列表臆造路径可能控制错误的 sysfs 设备。

## 测定缺失硬件

诊断包含有范围限制的 `[hardware]` 区块，列出输入设备名称、已绑定的 I²C 和 IIO 名称、温区类型及可能的继电器类条目。该报告识别出 `sun-ths` 和 `sun-hum` 输入设备；继电器路径仍未知。下一项有用的继电器证据是厂商 MQTT 服务的软件包名称，以及有人现场看护切换单个继电器时的有限流量。

针对 `sun-ths` 和 `sun-hum` 输入设备，请下载并运行下方只读采集器。将 `<panel-ip>` 替换为面板地址，再将完整命令行粘贴到可使用 `adb` 的同一 Git Bash、WSL、macOS 终端或 Linux 终端：

```bash
curl -fsSL https://raw.githubusercontent.com/panel-assistant/android/v0.9.11/scripts/collect-panel-hardware.sh -o collect-panel-hardware.sh && bash collect-panel-hardware.sh --serial <panel-ip>:5555 --observe climate
```

这只读取两个温湿度输入设备，不会更改面板。实时观察限制为 10 秒，每个准确传感器名称最多 32 个事件。分享前检查终端输出；如果命令报告错误，请改为分享该错误。2026-07-17 的 `adb shell` 报告确立了输入名称、轴及符合百分之一缩放的数值。要称为硬件已验证，仍需报告者将面板应用读数与厂商显示或外部温度计、湿度计比较。adb shell 可读取不代表普通应用有访问权限；面板应用使用已安装且受允许列表限制的辅助进程。
