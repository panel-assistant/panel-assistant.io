这是目前完整支持的面板中功能最丰富的一款：**10.1 英寸、1920×1200（约 226 ppi）** 的 rk3576 设备，配备 **4 GB RAM**、**无需 root、应用可直接控制的 RGB LED**、六轴运动传感器组和 **Google Play 服务**，因此 WebView 和应用可自行更新。固件还提供 Android 自带的导航栏。板上有 NFC 芯片，但尚不能使用。这些信息来自运行中实机的逆向分析（Android 14 `userdebug`、`adb root`）。

## 首次调试访问

**无需电脑、通过 TCP 端口 5555 使用网络 ADB 的方法：尚未确认。** 设备已运行 Panel Assistant，或固件提供 root，都不能证明新面板如何开启调试。

**首次开启 USB 调试的方法也尚未确认。** 请向供应商索取适用于确切固件版本的调试说明，并确认 USB 端口支持数据传输。如果提供 USB 调试，可使用 [USB 安装器](/zh-hans/install/install-over-usb/)；不要假定充电端口支持 ADB。此处没有经过验证的出厂菜单操作步骤。

检查 root 需要已建立可用的 ADB 连接。root 权限与首次调试访问是两个独立问题。

## 获取 adb 和 root 访问权限

WF1589T 出厂使用带 Google Play 的 `userdebug` 固件，因此可直接使用 `adb root`，也带有 `su`，不需要密码或后门。LED 可由应用直接控制（见下文），所以面板应用仅在关闭背光时通过固件自带的 `su` 使用 root。

```bash
adb root                     # userdebug → root adbd shell
adb shell su 0 id            # uid=0 → root confirmed
```

:::danger
WF1589T 带有 OTA 更新器（`com.elclcd.otaupdater`），可能撤销你的修改。启用 adb 后，使用 `adb shell pm disable-user --user 0 com.elclcd.otaupdater` 将其停用（可撤销）。参见[阻止不需要的更新](/zh-hans/hardware/guides/firmware-backup-and-restore/#stop-unwanted-updates)。
:::

## WebView：已由 Play 负责更新

WF1589T **带有 Google Play**，因此不同于 NSPanel Pro 和 TPA10，无需旁加载 WebView。从 Play 商店更新 _Android System WebView_，或使用 Play 的 WebView 开发通道，即可保持最新。各面板的情况见[更新系统 WebView](/zh-hans/hardware/guides/update-the-webview/)。

## Android 原生导航栏

WF1589T 固件绘制自己的返回、主屏幕和最近任务栏。全新配置下，内置配置文件默认采用 `Native` 导航栏模式，由 Android 提供这些控件，不绘制覆盖栏或唤出条。已有保存选项会保留。此能力按配置文件声明，而非在代码中绑定此型号；其他配置文件在验证其固件导航栏后也可声明支持。渲染器的全屏设置和 Android 仪表盘锁定仍可能隐藏系统栏。

## 显示密度：提高密度

出厂基础逻辑密度为 160 dpi，Android 大致按 1 dp 对应 1 px 渲染，因此按钮、文字和仪表盘卡片在**实际屏幕上非常小，难以触摸**。基础值是 Android 的布局参考值，并非面板的 226 物理 PPI。面板应用建议此面板使用 212 dpi，这是经过验证的起点；可按房间和仪表盘调整：

```sh
adb shell wm density 212        # ha-paneld starting point; `wm density reset` restores the 160-dpi base
```

212 dpi 时，有效画布约为 1449×906 dp。更高的值会放大触控界面、减少可见仪表盘内容；更低的值则相反。

## LED：`/dev/ledjni`（应用直接控制，无需 root）

`/sys/class/leds` 没有 RGB 节点（只有 `mmc1::`）。前置 RGB LED 通过字符设备驱动，该设备对所有用户可读写、标记为 `device`，SELinux 允许应用访问，因此普通应用**无需 root 或辅助守护进程**即可驱动。这是 LED 无需 root 途径的唯一面板类别。

面板应用通过 `Rk3576LedController` 驱动它，仅在能够打开 `/dev/ledjni` 时发布 LED 实体。

原厂 `com.gulukai.pwmlightdemo` 软件包也会打开此设备。其开机启动的前台服务不断让 LED 循环显示七种颜色，覆盖面板应用的命令，导致 Home Assistant 中上次命令状态与实际 LED 不同。设备协议不支持读回状态，所以两个应用无法共同提供真实状态控制。因此，WF1589T 配置文件在[厂商软件包](/zh-hans/manage/vendor-packages/)界面中建议停用此演示程序；停用仍需用户主动操作，且可撤销。

### `/dev/ledjni` 节点与 ioctl 协议

```text
/dev/ledjni   crwxrwxrwx  system system  u:object_r:device:s0
```

ioctl 协议依据厂商示例以净室方式逆向分析，没有捆绑厂商二进制文件；参见 [`led_jni.c`](https://github.com/panel-assistant/android/blob/main/app/src/main/cpp/led_jni.c)：

```c
int fd = open("/dev/ledjni", O_RDONLY | O_NOCTTY);
ioctl(fd, 0xa1, R);   // red,   0..15
ioctl(fd, 0xa2, G);   // green, 0..15
ioctl(fd, 0xa3, B);   // blue,  0..15
ioctl(fd, 0x99, 0);   // off
close(fd);
```

## 传感器：通过 `SensorManager` 提供六轴运动传感器

WF1589T 对壁挂面板而言较为少见：通过标准 `SensorManager` 提供完整运动传感器组，无需 root：`accelerometer`、`gyroscope`、`gravity`、`linear_acceleration` 和 `game_rotation_vector`。底层芯片为 Kionix **KXTJ9** 和 Bosch **BMA2xx** 加速度计。没有提供 `TYPE_LIGHT` 或 `TYPE_PROXIMITY`，因为没有安装相应传感器。

此主板没有绑定环境光、接近、温度或湿度传感器（相比之下，[TPA10](/zh-hans/hardware/panels/tuya/tpa10/) 四种都有）。

## 摄像头

GalaxyCore **GC05A2**（上表中的 I²C `4-0037`），2592×1944 传感器。Android 通过 `internal/0-1` 提供程序报告一个 `LIMITED` 硬件级别的摄像头，仅支持 `BACKWARD_COMPATIBLE`，`Facing: Front`，无闪光灯、无自动对焦。另有 `external/0-0` 提供程序，但没有连接设备，面板声明了 `android.hardware.camera.external`。

`IMPLEMENTATION_DEFINED`、`YUV_420_888` 和 `BLOB` 三种格式都提供 1280×720。HAL 声称在 30 fps 下拍摄 720p `BLOB` 会停顿一帧。该厂商静态拍摄数据不代表面板应用 H.264 视频流的开销。`android.control.aeAvailableTargetFpsRanges` 仅提供 `[15 30]` 和 `[30 30]`：没有固定 15 fps 的传感器模式，因此 15 fps 视频流依靠编码器节奏控制，而非传感器。

硬件 H.264 编码器是 `c2.rk.avc.encoder`，由 Codec2 HAL（`android.hardware.media.c2@1.1-service`）提供；此面板没有 OMX `media.codec` 进程。它带有别名 `OMX.rk.video_encoder.avc`，因此按名称选择在此面板和 TPA10 上都能找到组件，但它们位于 OMX 向 Codec2 过渡的两侧，是不同组件，不能假定行为相同。它声明支持 `176x144` 至 `4096x2160`、`2x2` 对齐、报告码率范围 1 bps 至 20 Mbps、32 个并发实例。不同于 TPA10，此面板还带有硬件 HEVC 编码器 `c2.rk.hevc.encoder`，但面板应用不使用它。

显示摄像头卡片的面板并非空闲。在实测仪表盘上，面板应用维持着两个活动的 `c2.rk.avc.decoder` 实例，因此编码会与同一 Rockchip VPU 上现有的解码任务竞争资源。

面板应用可将此摄像头作为**默认关闭**的功能提供。在设置的摄像头卡片上开启**摄像头**开关后，可调整**分辨率**、**帧率**和**比特率**（默认 720p、15 fps、2000 kbps），以及**曝光**补偿。它通过 `rtsp://<panel>:8554/live` 提供 H.264 视频流；麦克风可用且获准使用时也提供室内音频。Home Assistant 通过面板摄像头实体从此流获取静态图片。摄像头打开时，面板始终显示页面内容无法遮盖的红色指示器。摄像头实体详见[控制参考](/zh-hans/reference/api/)。

:::caution
不要在**此面板**自己的仪表盘上放置**此面板**的 Home Assistant 摄像头卡片。这会使面板在同一视频引擎上循环解码自身编码的视频，没有任何益处。
:::

## NFC：有芯片，但未接入 Android

**NXP NFC 控制器**绑定在 `i2c-7 0x28`（`nxpnfc` 驱动），带有 `/dev/nxpnfc` 节点（`crw------- root root`），但 `pm list features` **没有**报告 `android.hardware.nfc`：此固件未启用 Android NFC 服务和 HAL。芯片存在，但出厂状态下应用无法使用。要使用它，需要 NFC HAL 和 NfcService，或以 root 直接访问 `/dev/nxpnfc`。面板应用不使用它。

## 访问模型概览

- **LED：**应用直接控制（`/dev/ledjni`），无需 root 或守护进程。
- **运动传感器：**应用直接访问（`SensorManager`）。
- **NFC：**有芯片（NXP），但 Android NFC 未启用；出厂状态下仅 root 可访问。
- **导航：**通过配置文件的 `Native` 模式使用 Android 自带导航栏。
- **屏幕亮度、导航、文字转语音：**与其他面板一样使用标准 Android 途径。
- **关闭屏幕：**通过自带的 `su` 关闭背光电源。
