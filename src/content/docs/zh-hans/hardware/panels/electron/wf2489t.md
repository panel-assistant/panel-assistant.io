这是 **Electron**（深圳市 Electron Technology，ELC）使用其 `WF2489T` 主板制造的 10.1 英寸 rk3576 墙面平板，是 rk3576 [WF1589T](/zh-hans/hardware/panels/electron/wf1589t/) 的同系列型号。固件报告 `ro.product.odm.manufacturer=Electron`，品牌为 Electron 自有商标 Apolosign。最初引入此产品的零售商品信息将其称为 ZHICAI SMT1019；“ZHICAI TECHNOLOGY”是该商品信息上的店铺名称，而非制造商。

## 首次启用调试访问

**不使用电脑、通过 TCP 端口 5555 连接网络 ADB：尚未确认。** 有用户运行 Panel Assistant，或固件构建提供 root，都不能证明新面板如何启用调试。

**首次启用 USB 调试的步骤也尚未确认。** 请向供应商索取适合您准确固件版本的调试说明，并确认存在 USB 数据端口。如果支持 USB 调试，可使用 [USB 安装程序](/zh-hans/install/install-over-usb/)；不要假设充电端口提供 ADB。此处没有经过验证的工厂菜单操作顺序。

root 检查需要已经可用的 ADB 连接。root 访问与首次调试访问是两个独立问题。

## 不同固件构建的 root 访问

**目前存在两种固件构建，它们在最重要的一点上不同。** 零售机附带受限、无 root 的生产构建。供应商也会提供 `userdebug` 构建，一位报告者已重新刷入该版本。所有需要 root 的功能都取决于面板运行哪个构建，因此请先检查。

|              | 原装（生产版）                                                                                          | 供应商 `userdebug`                                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 构建         | `ZX-SMT1019-R157-V1.0A`                                                                                 | `ZX-SMT1019-R157-V2.0-…`（`Apolosign/WF2489T/WF2489T:14/…:userdebug/release-keys`）                                                                                           |
| Root         | **无**；不存在 `su`                                                                                     | **有**。`adb shell id` 已为 `uid=0`，应用的 `su 0 sh -c "<cmd>"` 形式经过实机确认，引用保持完整。`su -c` 返回 `su: invalid uid/gid '-c'`，这是调用方言不匹配，_不是_缺少 root |
| SELinux      | **Enforcing**，将 LED ioctl 限制于特权域                                                                | Permissive                                                                                                                                                                    |
| 验证启动     | 锁定                                                                                                    | `verified=orange flash=unlocked`；观察到 `/system` 为只读，尚未区分可写覆盖层和 dm-verity 状态                                                                                |
| RGB LED      | `/dev/ledjni` 可通过 `O_RDONLY` 打开，但沙箱应用的 **ioctl 被拒绝**（`EACCES`、`rc=-13`）；无应用侧途径 | 由 root 辅助进程驱动；据报告可用                                                                                                                                              |
| 完全关闭屏幕 | 无辅助进程时亮度归零                                                                                    | 配置文件通过已认证辅助进程使用 `bl_power`；尚无 SMT1019 端到端结果报告                                                                                                        |

两者共用：瑞芯微 **rk3576**（`ro.product.device=WF2489T`）、**1280×800** 10.1 英寸屏幕、约 4 GB RAM 和 64 GB 存储、Android **14**、`arm64-v8a`，**带有** Google Play 服务。

### 在 `userdebug` 构建上安装

即使面板已有 root，`/system` 仍显示只读，可能因为未挂载可写覆盖层，也可能因为 dm-verity 开启，导致辅助进程没有可在重启后保留的位置，配置过程停止。请先尝试无需重启的重新挂载。只有备用步骤会重启面板；重启时需要人在面板前，因为受 PIN 保护的面板在输入 PIN 前无法重新启动应用：

```bash
# Try this first — no reboot, and on a panel that already carries a scratch overlay it is the whole fix:
adb -s <panel-ip>:5555 root && adb -s <panel-ip>:5555 remount

# Only if that is refused. This REBOOTS the panel, so be in front of it and unlock any PIN afterwards:
adb -s <panel-ip>:5555 disable-verity && adb -s <panel-ip>:5555 reboot
adb -s <panel-ip>:5555 root && adb -s <panel-ip>:5555 remount
```

之后配置可完成，辅助进程在重启后仍保留（报告者已确认）。

## 主板提供的传感器和 I/O

## 面板应用支持

内置 [`smt1019.yaml`](https://github.com/panel-assistant/android/blob/main/app/src/main/assets/device-profiles/smt1019.yaml) 配置文件使范围狭窄的 `wf2489` 设备子字符串匹配优先于 WF1589T 配置文件较宽泛的 `rk3576_u` 型号匹配，避免 `WF2489T` 与另一 rk3576 面板冲突。它声明：

- **`hardware.led.mechanism: rk3576-ioctl-daemon`。** 已编译 ioctl 驱动仅通过已认证 root 辅助进程访问节点。实时检查会在辅助进程无法驱动节点时保持 LED 不可用且不发布，如报告中没有 `su` 的安装。
- **`platform.su_form: none`。** 原装固件没有应用可访问的 `su`，因此需要 root 的功能（evdev 按钮、CPU 调频策略、`bl_power` 屏幕关闭途径）不可用。
- **`hardware.screen_off: daemon-blpower`。** 配置文件通过已认证辅助进程使用 `bl_power` 关闭背光。这是完全关闭屏幕，允许渲染器停止在后台绘制。`ScreenController` 运行时依次尝试守护进程、直接 root、亮度归零。原装固件既无辅助进程也无直接 root 时使用亮度归零；已有 root 但无辅助进程的构建可使用直接 root。声明此能力途径会让原装配置每次关闭屏幕多一次被拒绝的套接字连接。尚无 SMT1019 此途径的端到端结果报告。

亮度、导航、文字转语音和 Home Assistant 实体等标准 Android 能力在两个构建上均可工作。配置文件声明麦克风，因此提供语音功能，已有用户报告可用。无 `su` 的原装安装无法驱动 LED 或仅 root 硬件。供应商构建可使用已认证辅助进程，其 LED 控制据报告可用。尚未识别硬件按钮。

**接近感应为实验性。** VI530x 驱动在用户空间启动前不报告任何内容，因此辅助进程先遵循厂商的通电、初始化、周期和启动顺序，再读取测量值。报告者证据确认 `ABS_HAT1X` 是以毫米为单位的距离，`ABS_WHEEL` 报告读数是否有效，因此原始值 1896 表示约 1.9 m。面板应用使用未缩放的距离，并采用与其他接近感应来源相同的面板引导设置和已保存校准，不依赖猜测阈值或极性。辅助进程完整 ioctl 启动和读取路径尚未在硬件运行；请在[后续报告](https://github.com/panel-assistant/android/issues/106)中报告结果。

**室温和湿度已启用。** 已验证的 root 辅助进程读取 GXHT30 的 `sun-ths` 和 `sun-hum` 输入设备。室内实体默认启用，辅助进程不可用时不发布数值。报告者证据（2026-08-14）确认原始编码：`sun-ths` 使用 `ABS_THROTTLE`，范围 -4000 到 12500；`sun-hum` 使用轴 `0x1d`，范围 0 到 10000。实机报告 2479 和 5704。这些值符合百分之一摄氏度和百分之一百分比，但**不能**证明物理准确性。依赖它们前，请与厂商显示或参考传感器比较。`sensors.room_temp_offset_c` 可校正面板自身热量造成的恒定温度偏差，不能校正比例错误或湿度校准。

:::caution
**配置文件的 root 提示描述原装构建，但不会否决内置辅助进程。** `su_form: none` 和 `app_can_su: false` 对零售固件是正确的。需要内置辅助进程时，面板应用检查实时 root，而非将这些提示视为证明。供应商构建的 `su 0 sh -c "<cmd>"` 形式两次达到 `uid=0`，且引用保持完整，因此应用可在那里安装匹配的辅助进程，无需写入 `/system`。原装面板只会未通过实时检查，保持不变。独立的重启持久辅助进程途径是另一回事，仍需上述重新挂载流程。
:::

## WebView

两种构建均带有 **Google Play 服务**，并均提供 `com.google.android.webview` **124.0.6367.179**，这是通过解包各 ROM 确立，而非推断。原装生产构建（`ZX-SMT1019-R157-V1.0A`，2026-02-05）是真正的 `user` 构建；供应商构建（`…-V2.0`，2026-07-30）为 `userdebug`。另有观察确认供应商构建的面板运行同一版本。

因为有 Play，**受支持的修复方式是从 Play 商店更新 _Android System WebView_**。此面板与 WF1589T 属于同类，不属于 NSPanel Pro 和 TPA10 的侧载类别。不要在此侧载 `com.android.webview` 构建：`framework-res.apk` 只将 `com.android.webview` 列为 `availableByDefault`，但已安装提供程序是 Google 软件包，因此有效提供程序列表由产品覆盖配置提供，侧载提供程序可能根本不会被选中。

Chrome 124 发布于 2024 年 4 月，能够运行当前 Home Assistant 前端，因此这是日常更新，而非其他面板面临的空白仪表盘紧急问题。
