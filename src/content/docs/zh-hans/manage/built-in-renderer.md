面板应用在自身的 WebView 中绘制 Home Assistant 仪表盘，而不是交给独立的仪表盘应用。这让它能在应用重启后快速返回仪表盘：在后台检查当前仪表盘列表的同时，可以重新打开 Home Assistant 为同一服务器、账户和主仪表盘设置验证过的上次仪表盘。如果 Home Assistant 报告该仪表盘已移除或账户默认值已更改，面板会转到当前选择。

仪表盘运行后，面板应用可以检测停滞的连接、释放 WebView 累积的内存，并控制渲染器崩溃的影响。内置连接也使仪表盘实体过滤成为可能。面板始终是单应用设备，只需安装和更新一个应用。

内置渲染器是显示仪表盘的首选方式，也是引导设置选择的方式。仍可选用独立仪表盘应用，例如面板需要多个 Home Assistant 服务器或原生通知时（参阅[限制](#限制)）。Assist 语音控制不依赖任何一种仪表盘应用：带麦克风的面板无论运行哪一种，都由面板自身的[语音助手](/zh-hans/manage/voice-assistant/)提供。

## 启动与恢复

渲染器使用 Home Assistant 文档公开的 `?external_auth=1` 接口，因此面板应用能够知道仪表盘何时已连接，而不是将页面视为黑盒。它会：

- 应用重启后重新打开上次验证过的仪表盘，同时在后台刷新 Home Assistant 的仪表盘列表。仍会先进行简短的兼容性检查。记住的仪表盘与 Home Assistant 服务器、账户及配置的仪表盘绑定，明确设置的仪表盘或仪表盘标签页始终优先。
- 屏幕关闭时冻结页面，唤醒时恢复，使夜间渲染器 CPU 使用量减少约 70%。
- 重新加载已打开但始终未连接的仪表盘。反复失败后会放慢重试，并显示明确的 **正在重新连接到 Home Assistant…** 屏幕，而非浏览器错误页面。
- 对可恢复的检查按逐渐增加的间隔重试。登录遭到永久拒绝时会停止重试并显示浏览器登录说明。Home Assistant 版本不受支持或 WebView 不兼容时，会说明需要更新什么，并等待更新。
- 屏幕关闭时通过不可见的重新加载释放累积内存。
- 控制渲染器崩溃的影响及频率。页面反复崩溃时，会退回管理启动器，而非整夜重启。
- Home Assistant 宣布正在停止或离线时，在面板显示原生通知，只有确认 Home Assistant 已恢复后才清除。

从屏幕最顶端向下拉可刷新，拉两次可完全重新加载。渲染器还支持可选的空闲时返回主仪表盘、自动播放相机流，以及使用用户安装的私有证书颁发机构进行 HTTPS 连接。**隐藏 Android 系统栏** 可提供铺满屏幕的仪表盘；从屏幕边缘滑动可重新显示系统栏。在使用应用软件导航栏的面板上，**仪表盘** 会将渲染器带到前台而不重新加载；**重新加载** 是独立的恢复操作。

**缩放（%）** 调整渲染器绘制仪表盘的大小，默认为 100%。渲染器会在 Home Assistant 侧边栏中添加 **应用设置** 入口，用于打开面板配置页面。首次运行时会隐藏停靠的侧边栏，并在空闲时保持连接；以后可以打开侧边栏或更改这些默认设置。独立的 **隐藏 Home Assistant 导航（原生）** 选项会请求前端在原生 kiosk 模式启用时移除导航。如果只是仪表盘尺寸不合适，请参阅[显示尺寸](/zh-hans/manage/display-sizing/)。

## 要求与兼容性

内置渲染器同时需要：

- **Home Assistant 2026.4.2 或更高版本**；以及
- 支持 Home Assistant 原生宿主接口所使用的安全 WebMessage 监听器的 Android System WebView。

大多数人只需较新的 Android System WebView。面板应用会先检查 WebView 功能并验证 Home Assistant 兼容性，再加载仪表盘。

如果面板显示 **需要升级 Home Assistant**，请升级 Home Assistant 并选择 **重试**。面板上的任何操作都无法替代该更新。

如果显示 **此面板的网页查看器过旧**，请按照[更新 WebView](/zh-hans/hardware/guides/update-the-webview/)操作。在尚未发布的 1.0.0-rc2 版本中，如果面板允许，从 Home Assistant 启动的面板应用更新也可以安装经过验证且兼容的 WebView。其他面板需要采用指南中的方式。更新 WebView 后，选择 **重试**。

内置渲染器绝不会退回隔离程度更低的桥接方式。Home Assistant 本身无法升级时，其他渲染器可能有所帮助，但面板上的任何仪表盘应用都使用同一个系统 WebView，因此没有哪种应用能绕过过时的 WebView。

## 设置方法

在全新或重置后的面板上，直接在面板选择 **初始设置**，或从笔记本电脑、手机打开其设置页面（使用默认端口时，例如 `http://<panel>:8888/setup`）。引导设置会选择渲染器、登录 Home Assistant、选择账户默认值或某个仪表盘及其具体标签页，并在首次加载仪表盘前询问实体过滤设置。授权在管理员浏览器中进行，因此无需在面板上输入凭据。

对于已完成设置的面板，在 Home Assistant 的面板设备页面选择 **访问**，然后打开 **设置**。在 **Home Assistant 连接** 下输入 Home Assistant URL 并选择 **浏览器登录**，然后将仪表盘应用选为 **内置渲染器**。

## 仪表盘外观与 Android 锁定

配置页面的高级设置包含三个独立控件，分别作用于不同层面：

| 配置选项                                          | 更改的内容                                                                                                                                    | **不会**更改的内容                                                                                                          |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **隐藏 Home Assistant 导航（原生）**（默认关闭）  | Home Assistant 连接后，请求其前端隐藏导航。仅限内置渲染器。                                                                                   | 不会锁定 Android、隐藏 Android 系统栏，也不会注入或更改仪表盘 CSS。如果 Home Assistant 拒绝或不支持该请求，仪表盘保持原样。 |
| **隐藏 Android 系统栏**（默认开启）               | 隐藏 Android 状态栏和导航栏，让仪表盘铺满屏幕。从边缘滑动可显示系统栏。仅限内置渲染器。                                                       | 不会阻止离开应用，也不会隐藏 Home Assistant 自身的菜单和导航。                                                              |
| **将 Android 锁定到仪表盘（实验性）**（默认关闭） | 有 root 时，隐藏 Android 系统栏，并在其他应用或最近任务打开后约三秒内返回所选仪表盘。这用于阻止随意使用，不能构成防范刻意操作人员的安全边界。 | 不改变仪表盘外观。无 root 时无效。重启后有 60 秒未锁定的恢复窗口，之后重新应用已保存的锁定设置。                            |

如果希望仪表盘更简洁，可在无需在面板上使用 Home Assistant 导航后开启 **隐藏 Home Assistant 导航（原生）**；**隐藏 Android 系统栏** 已默认开启。只有确实需要防止随意离开应用时，才开启 **将 Android 锁定到仪表盘**，并且必须先测试退出途径：配置页面、Home Assistant 开关、`adb`、快速点按左上角七次，或重启后的未锁定窗口。

## 实体过滤

:::caution
自动学习无法证明自定义卡片或动态模板的所有依赖，实体集合不完整可能导致卡片缺失或状态过时。更改仪表盘后，请检查学习到的集合，并确保随时能够关闭过滤器。
:::

过滤器仅适用于内置渲染器。它改变前端对 Home Assistant 的订阅，让 Home Assistant 在序列化状态并发送到面板之前完成过滤。其他仪表盘应用不受影响。[性能](/zh-hans/manage/performance/)说明了为什么这通常是慢速面板上最有效的改进。

### 自动流程

1. 在 Home Assistant 的面板设备页面选择 **访问**，打开 **设置**，再打开 **仪表盘**，选择 **内置渲染器** 并开启 **实体筛选**。
2. 打开 **实体** 选项卡，选择 **立即扫描仪表盘**。
3. 访问每个仪表盘标签页，使用控件、弹出窗口和条件内容，让面板观察它们运行时依赖什么。
4. 检查当前、建议和排除列表。固定自定义卡片或模板间接使用的实体，并处理表格上方显示的实体过滤检查项。
5. 候选集合就绪后，选择 **应用策略集合**。面板会先显示新旧实体数量，请您确认，然后使用过滤后的订阅重新加载仪表盘。

![面板网页界面的实体选项卡，显示实体订阅过滤器、当前订阅的实体和建议实体](/screenshots/ui-entities-dark.png)

实体页面会解释为何发现各个实体，记录手动固定和排除的实体，并将识别出的宽泛或动态规则保留显示，直到您修复它们或明确选择处理方式。仍可能存在它未识别的行为，因此开启过滤器后，请测试每个仪表盘标签页。如果有任何内容缺失，请先在配置页面关闭 **实体筛选** 并重新加载，然后再修改候选集合。

### 面板何时暂停显示仪表盘

开启自动过滤时，内置渲染器绝不会以未过滤状态打开 Home Assistant。在扫描生成它能确认的集合之前，面板会显示原生等待屏幕，而非仪表盘，原因有三种。首次扫描正在运行或失败时，面板会以逐渐加长的间隔重试，因为通常是 Home Assistant 尚未启动。如果 Home Assistant 拒绝面板凭据，等待屏幕会指出需要登录。如果扫描完成但发现无法界定范围的规则，例如策略生成的仪表盘或无界选择器，等待屏幕会要求作出决定：忽略标记的规则并继续、关闭过滤器，或在实体页面检查。这一决定可在面板上或网络中的任何设备上作出：在 Home Assistant 的面板设备页面选择 **访问**，然后打开 **实体**（使用默认端口时，例如 `http://<panel>:8888/entities`）。等待屏幕也会显示地址。

等待决定属于稳定等待状态，因此面板不会在等待期间重新扫描目录。进入稳定等待状态五分钟后，它会询问 Home Assistant 仪表盘是否改变，此后最多每小时询问一次；只有仪表盘配置或账户默认值确实变化、用户作出决定，或面板的 Home Assistant 设置变化时，才会重新扫描。

面板应用更新可能使面板重新检查已在过滤的仪表盘。如果此检查在原本已使用过滤器的仪表盘上标记了规则，面板会将该规则记录为已忽略，恢复此前运行的实体集合，并打开仪表盘，而不暂停显示；规则仍显示在实体页面，可在那里重新启用。这仅适用于更新引起的重新检查、此前已有已接受的过滤器，且恢复的集合非空的情况。对于永远不能忽略的规则，例如仪表盘过大而无法分析，仍会暂停渲染器。

### 模板和手动固定

面板应用不会运行仪表盘模板，因此无法知道模板返回哪些实体，也不会猜测。它对模板涉及的两类实体采取不同处理方式。

模板仅**读取**的实体，例如条件中检查的状态，无需处理。Home Assistant 自行渲染模板，并通过过滤器不会触及的独立订阅将结果发送给面板。这些实体本就不应出现在实体页面的列表中，添加它们只会扩大订阅，没有益处。

模板**返回**的实体则不同。它们成为仪表盘上的卡片，通过过滤后的订阅读取状态，因此必须包含在集合中。面板不运行模板就无法发现它们，选择继续通过实体发现检查也不会将它们加入；该选择只是允许自动更新在缺少它们的情况下继续。

要添加一个实体，请在实体页面顶部的搜索框输入其名称或 ID 的任意部分。搜索覆盖完整的 Home Assistant 目录，而非仅已发现的实体，并显示各表格中的匹配数量。将每个所需实体设为 **已固定**。手动固定会一直保留，直到您移除，即使仪表盘变化或重新扫描也不例外。

### 重置已学习的数据

当旧仪表盘证据或以前的手动决定使候选集合产生误导时，请在实体页面使用 **重置已学习的数据**。确认后，它会清除学习到的仪表盘成员和证据、手动固定与排除，以及忽略的安全决定。它保留已知正常的活动过滤器，以及用于显示候选名称的 Home Assistant 目录，并在启用学习时启动新扫描。因此，重置会重建候选集合，而不会立即将订阅扩大到所有 Home Assistant 状态。

## 主题

**仪表盘主题**（配置，然后内置渲染器）决定由谁选择浅色或深色：

- **跟随 Home Assistant**（默认值）将选择交给 Home Assistant。面板只提供起点：Android 13 及以上实时跟随系统设置，Android 10 至 12 在加载仪表盘时跟随系统设置，Android 9 及以下则由 **深色模式** 开关（配置，然后显示）设置。Home Assistant 内选择的主题优先于此起点。
- **环境** 根据自动亮度使用的房间模型选择浅色或深色。必须开启自动亮度；收到可用读数之前，跟随 Home Assistant。变化需要光照或黑暗持续整整一分钟。
- **深色** 和 **浅色** 由面板选择。适用于侧边栏隐藏、完全无法从面板访问 Home Assistant 个人资料页面的 kiosk 仪表盘。

强制主题仅更改浅色或深色部分。具名主题及其颜色完全保持原样，切回“跟随 Home Assistant”会将浅色或深色部分恢复为先前值，若此前未设置则恢复为自动。面板绝不会更改 Home Assistant 账户中保存的主题，因此设为深色的面板不会让手机也变暗。

有一种情况无法覆盖：如果此 Home Assistant 用户明确选择了浅色或深色，而非自动，该选择仍优先，因为覆盖它意味着更改与该用户登录的所有其他设备共享的设置。将用户主题设为自动，或为面板提供独立的 Home Assistant 用户后，面板的选择才会生效。发生此情况时面板会说明：网页界面的 **运行时诊断** 卡片会注明 Home Assistant 主题覆盖了仪表盘主题，`/diag` 报告的 `[renderer]` 行包含 `theme_overridden=true`。

面板自身网页界面独立于上述设置，始终跟随您用于查看它的浏览器。

## 改用独立仪表盘应用

如果面板需要[限制](#限制)中列出的某项功能，请打开配置页面，在 **仪表盘应用** 下选择其他已安装的仪表盘应用。切换立即生效。不要为此选择 **自动**，因为只要内置渲染器已就绪，“自动”就会使用它。

## 限制

- **不支持多个 Home Assistant 服务器或原生通知。** 需要这些功能的面板请保留独立仪表盘应用。Assist 语音控制不在此限制内：对于带麦克风的面板，无论激活哪种仪表盘应用，它都来自面板自身的[语音助手](/zh-hans/manage/voice-assistant/)。
- **没有全屏媒体扩展功能**，例如文件选择器或类似投屏的播放。这些不在范围内。
- 渲染 Home Assistant 前端仍需要**较新的系统 WebView**。过时的 WebView 会在网页界面中触发健康警告；请使用[适用于您面板的方法](/zh-hans/hardware/guides/update-the-webview/)更新。
- 浏览器登录和高级非交互式安装均无需 root。
