两块 Sonoff NSPanel Pro 86 并排连接到同一个 Home Assistant，各自显示同一仪表盘的相同副本。脚本同时点按两块屏幕，逐页操作；每块面板下方的计时器会在屏幕完成响应后停止。左侧面板在出厂固件自带的网页引擎上运行 Home Assistant Companion 应用，右侧面板在自行安装的网页引擎上运行 Panel Assistant。之后两块面板交换角色，再进行一轮比赛，避免面板本身的速度差异影响结果。

## 渲染：速度约为两倍

![录像 A：第一块面板运行 Companion 应用，第二块运行 Panel Assistant，同时竞速](/screenshots/drag-race-film-a.gif)

共七次触摸：三次切换页面、一次返回主页、三次点按灯光卡片。每种排列运行三次；录像展示中位数那次，两段录像之间面板交换角色。

|                            | Companion 应用，固件自带网页引擎 | Panel Assistant，自带网页引擎 |
| -------------------------- | -------------------------------- | ----------------------------- |
| 首次排列，三次运行的中位数 | 11.7 s                           | 6.4 s                         |
| 第二次排列，面板交换       | 14.3 s                           | 6.1 s                         |
| 绘制进程使用的处理器资源   | 1.3 至 1.5 核                    | 0.4 至 0.6 核                 |
| 仪表盘页面空闲时帧率       | 每秒 5 帧                        | 每秒 59 帧                    |
| 页面跟踪的实体             | 4,118                            | 54                            |

Panel Assistant 下的仪表盘页面只跟踪它显示的实体。Companion 应用下的页面会接收全屋数千个实体的每次状态变化，大部分时间都用于处理它们。因此，同一页面在一块面板上以每秒五帧绘制，在另一块上达到六十帧，而绘制进程消耗的处理器资源也相差两倍半。

![录像 B：面板交换后，第二块运行 Companion 应用，第一块运行 Panel Assistant](/screenshots/drag-race-film-b.gif)

## 延迟：真正影响使用的问题

秒表上快一倍，只算适度改进。这不是您在墙上感受到的差别。您感受到的是按下按钮，却没有任何反应的那一刻。

您按下按钮，期待发生变化。超过半秒仍无反应，您以为没有按中，于是又按一次。现在两次触摸都生效了：灯亮起后立即关闭，或者您请求的页面刚出现，又被第二次触摸请求的页面取代。您的操作完全正确，却得到相反结果。这样的面板不只是慢，而是无法使用；一周之后，家里没人再信任它。

![重复点按：两块面板上对同一灯光进行相同点按，遵循一秒无反应就再点一次的习惯](/screenshots/drag-race-double-press.gif)

还是同样两块面板、同样的灯光卡片，两边灯光均关闭。手指点按灯光，并遵循所有人都会遵循的规则：一秒后没有变化就再点一次，最多三次。

|                        | Companion 应用，固件自带网页引擎               | Panel Assistant，自带网页引擎 |
| ---------------------- | ---------------------------------------------- | ----------------------------- |
| 首次点按后灯光明显亮起 | 15.2 s，点按三次后                             | 0.3 s，点按一次后             |
| 另外两次拍摄           | 点按一次后 7 s；仍在加载页面，点按三次，无反应 | 每次都是点按一次后 0.3 s      |

十五秒意味着您已经放弃并走开，灯却在身后亮起。Companion 应用下的页面没有损坏：它正忙着在四核面板上消化全屋状态流，触摸只能排在这些工作后面等待处理。Panel Assistant 的页面只需要照看自身的实体，因此可以立即处理触摸。

## 测量方法

- 两块 Sonoff NSPanel Pro 86（四核 Rockchip PX30，480 × 480 屏幕），连接一个约有 4,100 个实体、每秒约 20 次状态变化的生产 Home Assistant。
- 同一个仪表盘的两份副本，除其中一个卡片控制的灯光外完全相同，避免两块面板争用同一实体。
- Companion 应用 2026.6.5 运行在固件自带的 Chromium 107 网页引擎上，大多数已安装面板仍使用该引擎。Panel Assistant 运行在 Chromium 138 上，这是本次测试采用的兼容网页引擎。
- 在两块面板上同时注入原始屏幕触摸事件。每一步由面板自身记录；计时从触摸开始，直到屏幕停止变化。如果某一步在片段结束时仍在变化，则该次运行作废。
- 每种排列运行三次，拍摄中位数那次。用于从互联网获取歌词的音乐卡片被移除，因为面板应用无法加速外部服务；实时相机页面也未纳入，因为其耗时来自流建立，而非仪表盘工作。

这些相同的指标也会实时显示在任何 Panel Assistant 面板网页界面的 **性能** 下；如何在自己的硬件上解读这些数据，请参阅[性能](/zh-hans/manage/performance/)。
