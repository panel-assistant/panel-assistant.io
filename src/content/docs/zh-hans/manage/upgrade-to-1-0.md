Panel Assistant 1.0 与 1.0 面板应用需要一同升级。1.0 集成只与 1.0 面板应用通信，1.0 面板应用也只与 1.0 集成通信，因此任一端都无法与 0.9 的另一端配合。请先更新集成，再从 Home Assistant 更新每块面板，而且**运行 1.0 应用的面板无法回退到 0.9**。开始之前，请阅读整页内容。

## 开始之前

**完成 0.9.0 需要完成的全部工作。** 运行 Panel Assistant **0.9.0**，打开 **设置**、**修复**。Panel Assistant 1.0 已无法将面板从 MQTT 迁移出来，也无法迁移仍运行旧 ha-paneld 应用的面板，因此会保持这两类面板原样。如果 0.9.0 为任何面板列出其中任一情况，请按照其修复项操作，直到面板完成迁移；[从 MQTT 迁移面板](/zh-hans/home-assistant/move-from-mqtt/)介绍了 MQTT 部分。如果使用的 Panel Assistant 早于 0.9.0，请先更新到 0.9.0 并让它完成迁移。

**创建 Home Assistant 备份。** 在 **设置**、**系统**、**备份** 下创建备份，并保留到所有面板均运行 1.0 且您对其表现满意为止。这是 Home Assistant 一侧的回退方式。

**保留每块面板的备份。** 在每块面板的网页界面中打开 **安装**，然后选择 **备份**，保留下载的 `.hpb` 文件。Panel Assistant 也会在每次更新前保存面板设置，但您自己的副本才是可以自行恢复的备份。

## 1. 更新集成

1.0 首先以候选发布版提供。打开 **设置**、**设备与服务**、**HACS**，选择 **Panel Assistant** 设备。展开已禁用的实体，打开 **预发布**。在其设置中开启 **已启用**，选择 **更新**，然后打开 **诊断** 下的 **预发布** 开关。返回 HACS 中的 Panel Assistant，下载 1.0 候选发布版。当 HACS 要求重启，或出现 **重启 Home Assistant 以完成 Panel Assistant 更新** 修复项时，重启 Home Assistant。

## 2. 检查修复项

重启后，再次打开 **设置**、**修复**。

- **“…需要应用 1.0.0-rc1”** 是所有仍运行 0.9 应用的面板都会出现的预期提示。更新之前，Home Assistant 无法查看或控制该面板，其实体显示为不可用。面板本身仍会继续工作，保留设置和历史记录。
- **“…无法接收应用更新”** 表示 Panel Assistant 无法在该面板上安装，通常是因为面板本身发生过更改，例如固件更新或重置。按照修复项 **了解更多** 中的说明，通过 USB 将面板重新连接到 Panel Assistant，之后即可更新。不会移除任何内容：对于已安装应用的面板，USB 安装程序不会安装任何东西，只会让 Panel Assistant 重新获得访问权限。
- **“…从未从 MQTT 迁移”** 或 **“…仍运行旧应用”** 表示在 0.9.0 中未完成迁移。参阅[如果迁移未完成](#如果迁移未完成)。

## 3. 先更新一块面板，再更新其余面板

1.0 面板应用的发布版本公布后，每块面板在 Home Assistant 中的更新实体都会提供该版本。请先在一块面板上安装，使用一段时间后再安装到其他面板，因为该面板无法回退。Panel Assistant 会备份面板设置、安装更新并确认面板已恢复正常，详见[更新与恢复](/zh-hans/manage/updates-and-recovery/)。0.9 面板应用的设置会保留。

## 回退

两部分的情况不同。

**使用 1.0 应用的面板会留在 1.0。** 面板应用拒绝在自身上安装旧版本，Panel Assistant 从不提供旧版本，0.9 集成也无法与其通信。如果 1.0 面板表现异常，请查看[故障排查](/zh-hans/manage/troubleshooting/)，然后附上[支持报告](/zh-hans/home-assistant/support-report/)进行反馈，以便在下一个候选发布版中修复。

**只要没有面板运行 1.0，集成就可以回退。** 恢复开始之前创建的 Home Assistant 备份。这也会撤销创建备份之后 Home Assistant 中的其他所有更改。面板仍运行 0.9 应用，并重新连接到 0.9.0。一旦任何面板运行 1.0 应用，恢复备份就会使 Home Assistant 无法访问该面板，直到集成重新升级到 1.0。

不要在 HACS 中重新下载 0.9.0 来覆盖 1.0，以此进行回退。1.0 更新会移除 0.9.0 依赖的一项设置；缺少此设置时，0.9.0 会将已迁移的面板重新交回 MQTT，而 1.0 面板应用已不再响应 MQTT。请改为恢复备份。

## 如果迁移未完成

如果 1.0 提示某块面板从未从 MQTT 迁移，或仍运行旧应用，修复项会要求您在 HACS 中选择 **重新下载**、选择 0.9.0，在那里完成迁移，然后再次安装 1.0。不要重新下载 0.9.0 来覆盖 1.0。只要尚无面板运行 1.0 应用，请基于上述原因，恢复更新之前创建的 Home Assistant 备份来返回 0.9.0。然后在 0.9.0 中完成迁移，再从头执行本页步骤。如果其他面板已经运行 1.0 应用，或者没有更新前的备份，请在更改任何内容之前到 [Discord](https://panel-assistant.io/go/discord) 或 [issues](https://github.com/panel-assistant/ha-integration/issues) 求助。

对于仍使用 MQTT 的面板，修复项还提供从头开始的方式：删除 MQTT 集成下的面板设备，再重新添加面板。这会创建新实体，且不保留任何历史记录。
