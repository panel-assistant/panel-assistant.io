本页介绍已停用的[命令行安装程序](/zh-hans/install/installing-ha-paneld/)的检查机制，该程序曾在 ha-paneld v0.9.9 之前用于安装面板。现在由 Panel Assistant 安装和更新面板：更改任何内容前会检查面板，每次更新前会备份设置，详见[更新与恢复](/zh-hans/manage/updates-and-recovery/)。

## 信任与凭据边界

凭据文件可避免机密出现在运行安装程序的计算机的 shell 历史记录和子进程命令行中，但不会为面板管理 API 增加加密。面板 API（例如默认端口下的 `http://<panel>:8888`）遵循项目的可信网络模型，因此代理凭据和 Home Assistant 令牌通过此连接以未加密 HTTP 传输。请仅在可信且分段隔离的网络中运行安装程序。[安全参考](/zh-hans/reference/security/)介绍了该模型。

使用 Home Assistant 用户名和密码登录的方式不同。密码从安装计算机发送到 Home Assistant 登录端点，绝不会到达面板。请使用 `https://` Home Assistant URL，使登录传输经过加密；`http://` URL 会明文发送密码。面板仅接收生成的刷新令牌，该令牌可以撤销。

配置导出包含机密，并以仅所有者可访问的权限写入；请将其视为凭据。升级前自动创建的设置和数据库副本也放在仅所有者可访问的目录中，文件权限为 600。

## 发布版本和软件包验证

无需检出仓库的安装程序会下载匹配的发布应用和部署程序。在更改面板之前，它根据由发布密钥签署的 SHA-256 记录验证已发布的应用和辅助程序二进制文件。它还会使用 Android Build-Tools 检查应用的软件包和签名者。在尚未安装面板应用的面板上首次安装时，这些工具可选，因为 Android 会在安装时自行检查签名；更新已有应用时则必须使用：安装程序会在更改任何内容前比较已安装版本与新版本的签名者，无法确定时拒绝操作，而不猜测。否则，签名者不匹配可能导致先停用运行中的辅助程序，再安装失败。安装程序会选择与面板报告的 ABI 匹配的辅助程序。

本地构建的应用采用独立的开发者途径。它仍必须包含 ha-paneld 软件包，且恰好具有一个有效签名者，但可以使用构建者自己保持一致的签名密钥。当本地文件应为官方构建时，`--require-release-signer` 会收紧检查。`--allow-unsigned-helper` 则单独确认辅助程序二进制文件由本地构建者控制，而非作为发布文件验证。

## 备份与恢复

三种文件分别用于三种恢复任务：

- **配置 JSON 导出**包含设置和机密。`--export FILE` 可明确创建导出，安装程序也会在普通升级前尝试自动创建仅所有者可访问的导出。它不包含运行时配置文件目录、配置文件选择、已学习的实体状态、历史记录，或独立仪表盘应用持有的 Home Assistant 登录状态。
- 在面板网页界面的 **安装**、**备份** 中创建的 **`.hpb` 备份**是支持范围内最完整的备份。它携带设置、持久面板状态、配置文件目录，以及独立仪表盘应用持有且符合条件的登录状态。已学习的实体目录、接近感应和环境光历史会重新学习，而非恢复。在同一页面通过 **安装**、**恢复** 还原 `.hpb`。安装程序的 `--restore FILE` 接受配置 JSON，不接受 `.hpb` 备份。
- 自动生成的 **`…break-glass.db`** 是面板内部数据库的最后恢复手段。不会有任何功能自动恢复它，且它仅适用于来源面板和来源应用版本。

当 `--export FILE` 与安装或配置选项组合使用时，会在面板上发生任何更改之前写入经过验证的导出。如果无法生成并验证，运行会停止。如果希望只导出而不安装任何内容，请先单独运行 `--export FILE`。

普通升级前的自动设置导出为尽力而为。如果无法创建，安装程序会移除不完整文件，记录没有设置导出，并继续替换应用。

卸载、清除应用数据或执行任何其他破坏性恢复之前，请单独通过 **安装**、**备份** 创建备份，并检查下载的 `.hpb` 非空。这些操作会销毁应用数据。普通的 `adb install -r` 会保留数据。

`--reset-config` 刻意采用不同方式。**重置不可逆，而且不创建备份。** 它要求单独确认，然后移除面板应用的全部数据。应用、辅助程序和其他 Android 应用仍保持安装。

## 自动数据库快照

每次普通升级前，安装程序都会尝试捕获面板数据库，其中保存配置、实体目录、接近感应和环境光历史，以及面板保留的修订历史。快照用于日后卸载或其他破坏性修复时辅助恢复；Android 正常的就地应用替换会将原数据库保留在原处。

安装程序仅通过 ADB 向运行中的应用发送一次升级准备请求。应用停止接受新工作、完成待写入内容、暂停数据库写入者、刷新状态、对 SQLite 预写日志执行检查点并关闭数据库。只有记录旧进程、应用版本、字节数、计算机可验证的 SHA-256、数据库架构版本和状态行数后，才会确认该确切请求。

安装程序直接从应用私有存储复制已关闭的数据库，不在面板上暂存第二份副本。计算机上的副本只有在大小和始终会检查的 SHA-256 与确认信息一致，且通过本地 SQLite 完整性、架构和行数检查后，才会被接受。

如果应用未返回确切的确认，例如请求超时或响应格式错误，安装程序会回退一次到 SQLite 的实时 `.backup`。这同样生成一个自包含的数据库文件，旁边没有预写日志或 journal 文件。没有 root 途径的面板无法提供私有数据库，因此可能只有设置导出可用。

对于普通就地升级，数据库备份为尽力而为。失败或不一致的副本会被移除，安装程序会显示醒目警告，但可以继续替换应用，原应用数据保持不变。无效副本绝不会被保留或标记为成功备份。

此备份没有固定的可用空间阈值。正常途径不在面板上暂存内容，唯一的回退方式会通过实际捕获判断是否容得下。存储压力、数据库健康检查失败、状态端点无法访问、响应格式错误或无法识别的状态，都会在安装前后报告。它们都不会阻止普通应用替换，因为新构建可能是旧构建不健康或无法访问时唯一有用的恢复尝试。如果需要严格的通过或失败结果，可单独使用 `--verify`，它会将这些情况报告为失败。

## 时区和首次安装检查

更改面板之前，安装程序会比较面板与计算机的时区。不一致时只警告而不停止，因为面板可以合理地使用不同时区。比较使用时区名称而非当前 UTC 偏移，并通过计算机的时区数据库解析已知别名。这能发现仍使用出厂默认时区的面板，否则日志时间和计划任务可能对应错误的本地时间。

如果任一值无法确定，检查保持静默。缺少响应、无效时区名称或计算机时区数据库未知的别名，都不会导致安装失败或改变安装。

干净面板没有面板应用的状态端点，部分损坏的安装也是如此。安装程序会先询问 Android 软件包管理器 ha-paneld 是否已安装，再决定属于哪种情况。明确的“未安装”会启动正常的首次安装。如果软件包管理器或 ADB 查询没有响应，则在更改面板之前停止。

## root 辅助程序升级

发布版本包含封装的 `armeabi-v7a` 和 `arm64-v8a` 辅助程序二进制文件。在具有厂商 `su` 或 root ADB 的面板上，安装程序使用发布密钥验证所选二进制文件，暂存后再次验证，并原子地安装或升级。替换应用之前，它会检查应用需要的协议功能和可复现构建身份。

旧的 root 所有辅助程序及其服务会保持可用，直到应用安装成功。如果辅助程序安装或启动失败，或身份、功能错误，会在替换应用之前恢复上一组可用的辅助程序和服务。如果 Android 安装应用时 ADB 连接断开，安装程序会保留恢复日志。再次运行同一命令会验证已安装应用和运行中的辅助程序，然后完成或回滚中断的升级。

恢复快照归 root 所有，通过已记录的摘要验证，并在停用实际文件之前同步到存储。如果存在未完成的辅助程序事务，安装程序会拒绝开始，并指出需要重新运行的命令。

当能够验证空间充足时，安装程序优先在可写的 `/system` 上使用 init 服务。如果 `/system` 只读，则在 `/data/adb/service.d` 中使用已验证的 Magisk、KernelSU 或 APatch 运行器。如果 `/system` 可写但空间紧张，可以将辅助程序和恢复文件保留在 `/data/adb/hapaneld`，仅将启动服务放在 `/vendor/etc/init`；以后更新会保留该已验证布局。如果无法确定存储容量、启动由谁管理，或现有事务的状态，安装程序会在替换应用之前停止。

应用携带匹配的辅助程序作为回退。如果通过直接 `su` 安装的面板尚未再次运行安装程序，就从安装选项卡或 Home Assistant 更新实体更新，应用首次启动时会检查所需的辅助程序协议，并可从 `/data/local` 启动 root 所有的副本。将 root 限制在沙盒中的已 root 面板无法安全地让旧辅助程序替换自身，因此会拒绝继续，并要求从计算机运行经过验证的安装程序。

## 什么情况会停止运行

如果无法安全确认所请求操作需要的条件，安装程序会以非零结果停止。例如软件包查询无响应、应用软件包或签名者错误、辅助程序事务无法恢复、所请求的配置导出无法验证，或安装后必须进行的自检失败。

其他发现仅为警告，因为停止会增加恢复难度。自动数据库备份不可用、存储健康警告或升级前状态调用失败，本身不会阻止普通就地应用替换。安装程序会明确说明这一限制，而不会将部分或无效的恢复文件呈现为成功。

### 理解拒绝信息

每条拒绝信息都会指出一个条件，除非另有说明，否则不会更改面板上的任何内容。措辞会指向需要修复的事项，因为不同情况的补救方式差别很大。

- **读取规范数据库时，它一直在变化。** 安装程序尝试创建一致副本时，面板应用仍在写入数据库。这表示面板忙碌，不表示损坏。复制会自动重试，因此看到此信息意味着应用在每次尝试期间都持续写入；通常在面板较空闲时重新运行安装程序即可。
- **无法读取规范数据库**，或**它不是普通文件。** 这是相反的情况，涉及存储数据而非应用：文件缺失、不是文件，或根本无法打开。重试之前请恢复数据库。
- **应用已安装，但规范数据库缺失。** 应用存在但其存储不存在，普通升级无法解决。请恢复备份，而非重试。
- **安装目标为只读。** 安装特权辅助程序的目录位于以只读方式挂载的文件系统上。多数面板无需重启即可重新挂载为可写。安装程序会报告实际测量的文件系统，请先检查该行，不要猜测指的是哪个分区。
- **安装目标没有空间，或没有可用 inode。** 两者都会报告测量结果，分别列出是因为面板可能某一种资源耗尽，另一种仍很充足。
- **无法协调此前未完成的升级。** 之前运行留下的恢复记录无法与当前安装状态对应。不会更改任何内容。需要检查恢复记录，而不是再次重试，因为重试会得到相同结论。
- **后继应用部署一段时间后，原应用仍已安装。** 新应用已安装，但在安装程序等待窗口内未移除旧应用。面板正常工作；未完成的是移除操作。

提及回滚的拒绝信息会说明是否验证了回滚。“已回滚并验证”表示面板与运行前相同。“无法验证回滚”表示即使应用本身未被替换，也应先检查特权辅助程序，再依赖特权操作。
