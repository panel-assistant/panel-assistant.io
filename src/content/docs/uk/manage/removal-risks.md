Panel Assistant видаляє ha-paneld одним кроком через пункт **Видалити Panel Assistant з цієї панелі** у розділі **Налаштувати** в Home Assistant (Panel Assistant 0.9 називає його «Видалити ha-paneld з цієї панелі»). На більшості панелей цього достатньо. На деяких видалення залишає панель без шляху до налаштувань Android чи мережевого налагодження, і тоді ніщо, зокрема Panel Assistant, не зможе знову встановити на неї застосунок, доки ви не скористаєтеся власним способом відновлення виробника. На деяких прошивках цей спосіб означає вхід до облікового запису виробника або під’єднання комп’ютера через USB.

У ще не випущеній версії 1.0.0-rc2 цей пункт називається **Видалити з цієї панелі**, а успішне видалення також видаляє панель із Home Assistant; можливості зберегти її запис немає. На сторінці пристрою панелі також є кнопка **Видалити з цієї панелі**. Її натискання нічого не видаляє: воно відкриває постійний запит на виправлення проблеми **Прибрати Panel Assistant з &lt;panel&gt;** у розділі **Налаштування → Система → Виправлення проблем**. Прочитайте попередження в ньому, перш ніж підтвердити видалення одним натисканням **Надіслати**. Якщо ви натиснули кнопку помилково, закрийте діалогове вікно без надсилання й залиште запит на виправлення проблеми непідтвердженим.

Видалення запису панелі в Home Assistant залишає ha-paneld встановленим. Перш ніж видаляти запис, скористайтеся описаним вище параметром видалення, щоб видалити застосунок.

Якщо ви вже видалили запис, знову додайте панель у Home Assistant, а потім скористайтеся описаним вище параметром видалення.

Прочитайте розділ для своєї панелі, перш ніж підтверджувати.

## Що робить видалення

1. ha-paneld повертає головний екран власному лаунчеру панелі й знову вмикає застосунки виробника, які вимкнув.
2. Panel Assistant перевіряє на панелі, що інший лаунчер справді володіє головним екраном. Якщо ні, зупиняється й нічого не видаляє.
3. Panel Assistant видаляє ha-paneld через своє керівне з’єднання. Налаштування ha-paneld на панелі видаляються.
4. У 1.0.0-rc1, якщо перед надсиланням ви вибрали **Також видалити цю панель із Home Assistant**, Home Assistant також забуває панель. Залиште вимкненим, щоб зберегти її сутності й історію. У ще не випущеній версії 1.0.0-rc2 успішне видалення завжди видаляє запис.

Якщо видалення зупиниться посередині, запустіть його знову: воно продовжить із місця зупинки.

## Повторне встановлення на цій панелі

Спочатку відновіть налагодження, скориставшись розділом для вашої панелі нижче та інструкцією [Підготовка панелі](/uk/install/prepare-a-panel/#1-параметри-розробника-та-налагодження-увімкнено). Потім дотримуйтеся інструкції [Додавання панелі](/uk/install/installing-ha-paneld/), щоб знову встановити Panel Assistant. Видалення стирає налаштування застосунку; повторне встановлення їх не відновлює.

## Чому панель може застрягти

Якщо постійний мережевий ADB увімкнений і підтримується, ha-paneld може відновити його після перезапуску. Після видалення цієї підтримки немає, а прошивка виробника може вимкнути налагодження, зокрема після перезапуску.

Це важливо лише якщо власний головний екран панелі не має шляху до налаштувань Android, де налагодження вмикається знову. Кілька головних екранів виробників його не мають.

## Sonoff NSPanel Pro

<div class="removal-make" data-make="sonoff">

Головний екран eWeLink не має шляху до налаштувань Android, тому версія прошивки визначає складність повернення налагодження.

- **Прошивка 4.0.0 і новіша:** Sonoff додав пункт F-Droid у меню панелі, а встановлені з нього застосунки відкриваються з цього меню. Перед видаленням ha-paneld встановіть лаунчер застосунків із F-Droid, який показує налаштування Android серед застосунків панелі, щоб згодом знову ввімкнути налагодження.
- **Прошивка нижче 4.0.0:** немає магазину застосунків і шляху до налаштувань Android із панелі. Якщо панель уже прив’язана до облікового запису eWeLink, налагодження знову вмикається з телефонного застосунку eWeLink: торкайтеся _Device ID_ в налаштуваннях пристрою панелі, доки не з’явиться _Developer mode_, потім увімкніть там ADB. Подальша прив’язка панелі до облікового запису може не спрацювати: на одній панелі код сполучення залишався сірим в очікуванні. Без прив’язаного облікового запису залишається завантаження у відновлення з комп’ютером, під’єднаним через USB: див. [Отримання доступу adb і root](/uk/hardware/panels/sonoff/#gaining-adb-and-root-access). Якщо панель прив’язана до eWeLink, оновіть її там до 4.0.0 або новішої перед видаленням ha-paneld.

Порівнювати треба номер прошивки, який показують застосунок eWeLink і Panel Assistant, наприклад 4.0.12, а не внутрішній `ro.product.version`. Див. [особливості прошивок за версіями](/uk/hardware/panels/sonoff/#firmware-quirks-by-version).

## Shelly Wall Display

<div class="removal-make" data-make="shelly">

Головний екран Shelly не має шляху до налаштувань Android. На X2i параметри розробника відкриваються із застосунку налаштувань Shelly: див. [розблокування режиму розробника](/uk/hardware/panels/shelly/wall-display-x2i/#unlocking-developer-mode). На інших моделях Wall Display такого способу не підтверджено, тому вважайте видалення незворотним, якщо не знаєте, як знову ввімкнути налагодження.

</div>

## Tuya TPA10

<div class="removal-make" data-make="tuya">

Параметри розробника відкриваються із застосунку налаштувань панелі (торкніться номера версії сім разів), а налагодження USB працює через діагностичний застосунок: див. [Отримання доступу adb і root](/uk/hardware/panels/tuya/tpa10/#gaining-adb-and-root-access). Якщо мережеве налагодження вимкнули, для нього знову потрібен цей крок із USB.

</div>

## Інші панелі

<div class="removal-make" data-make="other">

Якщо власний головний екран панелі може відкривати налаштування Android, видалення залишить її такою, як до ha-paneld. Якщо ні, переконайтеся, що маєте інший спосіб увімкнути налагодження перед видаленням ha-paneld, наприклад лаунчер, що відкриває налаштування.

## Перевірка перед видаленням

- **Знайдіть версію прошивки.** Panel Assistant показує її вгорі цієї сторінки, коли посилається сюди. Натисніть **Відвідати** на сторінці пристрою панелі в Home Assistant, щоб відкрити власну сторінку ha-paneld (наприклад, `http://<panel>:8888` із типовим портом), де її вказано як _Прошивка_.
- **Знайте шлях повернення до налагодження** для своєї панелі й прошивки з розділу вище.
- **Збережіть лаунчер, що відкриває налаштування Android**, якщо головний екран виробника цього не має.
- **Не перезапускайте панель** між видаленням ha-paneld і завершенням усіх дій, для яких ще потрібне налагодження.

<script>
  // Panel Assistant links here with the panel's make, model and firmware
  // (make, model, fw). Each is optional; an unrecognised value is ignored.
  (() => {
    const query = new URLSearchParams(location.search);
    const clean = (value) =>
      value && /^[0-9A-Za-z][0-9A-Za-z ._+-]{0,79}$/.test(value) ? value : null;
    const make = clean(query.get('make'));
    const model = clean(query.get('model'));
    const fw = clean(query.get('fw'));
    const lower = (make || '').toLowerCase();
    const key = ['sonoff', 'shelly', 'tuya'].find((name) => lower.includes(name));
    if (!make && !fw) return;
    const box = document.getElementById('removal-this-panel');
    const name = [make, model].filter(Boolean).join(' ') || 'Невідома панель';
    document.getElementById('removal-this-panel-name').textContent =
      fw ? `${name}, прошивка ${fw}` : name;
    let verdict = 'Див. нижче розділ для вашої панелі.';
    if (key === 'sonoff' && fw && /^\d+(\.\d+)*$/.test(fw)) {
      const major = Number(fw.split('.')[0]);
      verdict =
        major >= 4
          ? 'Ця прошивка має F-Droid у меню: встановіть із нього лаунчер застосунків перед видаленням ha-paneld.'
          : 'Ця прошивка не має шляху до налаштувань Android із панелі. Для повернення налагодження потрібен телефонний застосунок eWeLink з уже прив’язаною до облікового запису панеллю або завантаження у відновлення з комп’ютером. Якщо вона прив’язана, спочатку оновіть її до 4.0.0 або новішої.';
    }
    document.getElementById('removal-this-panel-verdict').textContent = verdict;
    box.hidden = false;
    const section = document.querySelector(`.removal-make[data-make="${key || 'other'}"]`);
    if (section) section.classList.add('removal-make-match');
  })();
</script>
