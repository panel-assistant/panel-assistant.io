Для використання ha-paneld не потрібно його збирати: встановлення панелі завантажує підписаний випуск. Ця сторінка призначена для учасників розробки та тих, хто підтримує форк. Огляд вихідного коду див. в [огляді коду на DeepWiki](https://deepwiki.com/panel-assistant/android).

## Інструменти

Застосунок панелі — це Android-застосунок, написаний на Kotlin і зібраний Gradle. Йому потрібні **JDK 17** та Android SDK із **platform 37.0, Build-Tools 36.0.0, NDK 27.0.12077973 і CMake 3.22.1** (CMake і NDK збирають нативний драйвер світлодіода). Gradle wrapper фіксує версію Gradle, а версії залежностей містяться в [`gradle/libs.versions.toml`](https://github.com/panel-assistant/android/blob/main/gradle/libs.versions.toml).

Коли ці інструменти встановлено локально:

```sh
./gradlew :app:assembleDebug      # debug APK -> app/build/outputs/apk/debug/
./gradlew :app:assembleRelease    # release APK (unsigned unless signing configured)
```

## Docker

Якщо ви не хочете встановлювати нічого, крім Docker, [`tools/build/`](https://github.com/panel-assistant/android/tree/main/tools/build) збирає образ Docker і запускає в ньому Gradle. Його Dockerfile перелічує пакети SDK, включені в образ. APK потрапляє у ваше робоче дерево, образ кешується після першого збирання, а кеші Gradle зберігаються в іменованому томі Docker.

```sh
./tools/build/build.sh                       # debug APK -> app/build/outputs/apk/debug/
./tools/build/build.sh :app:assembleRelease  # any Gradle task(s) instead
```

Якщо ви запускаєте скрипт усередині контейнера, що звертається до зовнішнього демона Docker, прочитайте примітку `HOST_WORKDIR` у `build.sh`.

## Devcontainer

[`.devcontainer/`](https://github.com/panel-assistant/android/tree/main/.devcontainer) фіксує ті самі інструменти Android для VS Code, тому SDK і NDK не потрапляють на вашу машину. Відкрийте репозиторій у VS Code, виберіть **Reopen in Container**, а потім виконайте наведені вище команди Gradle. JDK у devcontainer новіший за JDK 17, тому щодо поведінки версії Java вважайте збірку на JDK 17 авторитетною.

## Root-помічник

Gradle автоматично збирає й перевіряє обидва root-помічники для відповідних ABI перед збиранням застосунку. Застосунок і помічники містять однаковий ідентифікатор, отриманий із кожного вихідного файла, заголовка й визначення команд помічника, тому локальна збірка застосунку не може непомітно залежати від застарілого привілейованого коду.

## Вимірювання продуктивності інформаційної панелі з комп’ютера

Власна сторінка стану панелі показує продуктивність для щоденного використання; див. [Продуктивність](/uk/manage/performance/). Для записаного порівняння інформаційної панелі з фільтром сутностей і без нього, виміряного ззовні панелі, у репозиторії є скрипт збору.

Якщо інформаційна панель без фільтра перевантажує власний WebView, показники на сторінці можуть перестати змінюватися. Скрипт збору на комп’ютері натомість опитує власний інтерфейс продуктивності застосунку панелі, що належить до застарілого REST API (див. [довідник керування](/uk/reference/api/#the-rest-api-is-deprecated)). Тому CPU всієї панелі залишається видимим, а за наявності root або допоміжного процесу — і нативне вимірювання потоку засобу відображення Chromium. Скрипт також записує вік останнього пакета браузерних вимірювань; усе старше за 15 секунд позначається як зависле, а не актуальне.

Скрипт збору не змінює конфігурацію. Він ніколи не вмикає, не вимикає й не переписує фільтр сутностей; перший запит може створити один приватний ключ інсталяції у внутрішньому стані застосунку панелі. Виберіть той самий вигляд інформаційної панелі й навантаження для обох запусків, змініть фільтр у вебінтерфейсі панелі, дочекайтеся перезавантаження інформаційної панелі, а потім виконайте по одній команді з робочої копії [репозиторію ha-paneld](https://github.com/panel-assistant/android) для кожного стану:

```bash
python3 tools/measure-dashboard-performance.py collect --panel http://192.168.1.50:8888 --expect filtered --label filtered --output filtered.json
```

```bash
python3 tools/measure-dashboard-performance.py collect --panel http://192.168.1.50:8888 --expect unfiltered --label unfiltered --pair-with filtered.json --output unfiltered.json
```

Порівняйте два результати:

```bash
python3 tools/measure-dashboard-performance.py compare filtered.json unfiltered.json --output comparison.json
```

Кожен запуск типово триває три хвилини з 30-секундним прогріванням і опитуванням кожні 10 секунд. `--pair-with` повторно використовує непрозорий ідентифікатор порівняння з першого результату, щоб відхилити іншу фізичну панель, інший налаштований Home Assistant чи інформаційну панель або змінене налаштування, що впливає на вимірювання, без запису цих приватних значень. Він не може виявити вручну вибраний інший вигляд у межах тієї самої інформаційної панелі, тому зберігайте видимий вигляд і навантаження однаковими.

Скрипт відхиляє запуск, якщо очікуваний режим неактивний, змінюється ревізія фільтра чи покоління засобу відображення, під час збору змінюється збірка або конфігурація, фільтрування переходить до запасного режиму або збережено менш ніж три зразки загалом, три зразки CPU всієї панелі чи три зразки нативного CPU засобу відображення. Він усе одно записує відхилений результат із точними причинами й ніколи не перезаписує наявний вихідний файл.

JSON не містить URL та ID панелі, URL Home Assistant і шляху інформаційної панелі, ID сутностей, назв процесів і хешу фільтра. Панель обчислює непрозорі відбитки за допомогою приватного випадкового 256-бітного ключа інсталяції, який ніколи її не залишає. Відбитки унікальні для однієї пари порівняння, тому окремі вимірювання не можна пов’язати через них чи використати для вгадування назви панелі. Панель, яка не може зберегти ключ, відмовляє у вимірюванні. Кількість сутностей без фільтра — остання синхронізована кількість із каталогу, а не поточний підрахунок із перевантаженого WebView; за порожнього каталогу вона недоступна. Лічильники мережевого й браузерного трафіку нормалізовано до фактично спостережених інтервалів, тому пропущене опитування не спотворює порівняння. Застарілі браузерні часові показники й швидкості трафіку виключаються з підсумків, тоді як CPU, пам’ять, мережеві та інші показники засобу відображення від самого застосунку панелі продовжують збиратися.

## Підписування

Для збирання й запуску ha-paneld не потрібно налаштовувати підписування. Копія репозиторію без налаштувань підписування використовує збережений у репозиторії `debug.keystore` для налагоджувальних збірок. Якщо `keystore.properties` задає налаштування підписування, налагоджувальні збірки використовують той ключ. Офіційні випуски підписуються приватним ключем випуску проєкту, якого ніколи немає в репозиторії.

Android відмовляється оновлювати встановлений застосунок APK-файлом, підписаним іншим ключем. Тому перехід панелі між офіційним випуском, вашим ключем випуску та налагоджувальною збіркою потребує попереднього видалення. Перед цим створіть повну зашифровану резервну копію `.hpb` через **Встановлення → Резервна копія** та перевірте, що файл збережено; інакше видалення забере профілі, вивчений стан та історію. Panel Assistant робить застосунок панелі адміністратором пристрою, а Android відмовляється видаляти адміністратора пристрою, тому спочатку звільніть його від цієї ролі. Або видаліть застосунок через пункт **Видалити з цієї панелі** у розділі **Налаштувати** в Home Assistant, або звільніть адміністратора пристрою й видаліть через ADB:

```sh
adb shell am broadcast --include-stopped-packages -n io.panelassistant.android/io.panelassistant.android.platform.ReleaseDeviceAdminReceiver
adb shell pm uninstall io.panelassistant.android
```

Якщо `pm uninstall` усе ще відповідає `DELETE_FAILED_DEVICE_POLICY_MANAGER`, зачекайте секунду й виконайте ще раз. Встановіть іншу збірку, а потім відновіть копію через **Встановлення → Відновлення**. Див. [Оновлення та відновлення](/uk/manage/updates-and-recovery/).

Щоб стабільно підписувати власні збірки, скопіюйте [`keystore.properties.example`](https://github.com/panel-assistant/android/blob/main/keystore.properties.example) до `keystore.properties` і заповніть його; за наявності цього файла `assembleRelease` підписується ключем випуску. Форк, що публікує теговані випуски через GitHub Actions, натомість надає той самий ключ як секрети репозиторію.

```sh
keytool -genkeypair -storetype PKCS12 -keystore release.jks -alias ha-paneld \
  -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=ha-paneld"
```

:::danger
Ніколи не комітьте `keystore.properties` або файл `.jks` (обидва ігноруються Git). Зробіть резервну копію сховища ключів і його пароля: якщо втратите їх, більше ніколи не зможете опублікувати оновлення власних збірок зі збереженням встановленого застосунку.
:::
