Home Assistant — спосіб автоматизації й моніторингу панелі. Panel Assistant публікує кожну панель як пристрій із сутностями й службами; там є все потрібне автоматизації чи інформаційній панелі. На цій сторінці перелічено сутності, власні сторінки й кінцеві точки панелі та стан REST API.

## Сутності Home Assistant

Підтримувані сутності з’являються в Home Assistant без YAML. Типові ID сутностей мають наведені нижче форми, де `<panel>` — налаштований ID панелі. Апаратні сутності пропускаються, коли активний профіль пристрою оголошує відсутність можливості; необов’язкові сутності налаштувань і діагностики можна окремо показати чи приховати на сторінці **Налаштування**.

Вимкнення відповідає активному профілю: фізичне вимкнення підсвічування, якщо панель його надає; сон Android, де підтверджено спосіб `keyevent`; або безпечне зменшення яскравості як запасний варіант. Сутності конфігурації, продуктивності й діагностики з реєстру публікуються лише коли їх показано на сторінці **Налаштування**. Необов’язкові діагностичні датчики: час останнього завантаження, використання CPU, використання пам’яті, температура SoC, IP-адреса, мережа Wi-Fi, рівень сигналу Wi-Fi та перебої Wi-Fi (24 год).

## Автоматизація панелі з Home Assistant

Використовуйте сутності панелі й стандартні служби Home Assistant; звертатися до самої панелі не потрібно.

- **Відтворити аудіо чи оголосити.** Викличте `media_player.play_media` для сутності медіапрогравача панелі з URL чи медіаджерелом. Задайте `announce: true` для мовлення поверх поточного відтворення. `media_player.media_pause`, `media_player.media_play`, `media_player.media_stop`, `media_player.volume_set` і `media_player.volume_mute` працюють як на будь-якому медіапрогравачі.
- **Задати гучність.** На панелі з динаміком використовуйте `media_player.volume_set` для її сутності медіапрогравача. Панель без динаміка натомість має числову сутність гучності; використовуйте для неї `number.set_value`.
- **Керувати екраном та інформаційною панеллю.** Використовуйте світло екрана, текстові сутності переходу й головної інформаційної панелі та кнопку перезавантаження інформаційної панелі.
- **Спостерігати за панеллю.** Стежте за датчиком стану, його атрибутами та наведеними вище діагностичними датчиками. Вони замінюють опитування рядка справності зі скрипту, а Home Assistant зберігає їхню історію.

```yaml
action: media_player.play_media
target:
  entity_id: media_player.wall_panel_media_player
data:
  media_content_type: music
  media_content_id: https://example.com/doorbell.mp3
  announce: true
```

Аудіо через HTTPS використовує сховище довіри платформи Android і перевірку імені хоста. Самопідписаний сертифікат відхиляється, якщо його CA не встановлено на панелі; звичайний HTTP залишається доступним для довірених джерел локальної мережі.

## Власні сторінки й кінцеві точки панелі

Виберіть **Відвідати** на сторінці пристрою панелі в Home Assistant, щоб відкрити локальну сторінку панелі. Кожна панель обслуговує невеликий фіксований набір шляхів на своєму HTTP-порті, типово `8888` (наприклад, `http://<panel>:8888/`). Решта не документується й не обіцяється.

| Шлях                         | Призначення                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                          | Стан панелі, можливості, діагностика й поточний попередній перегляд інформаційної панелі. Це `configuration_url` пристрою Home Assistant.         |
| `/setup`                     | Покроковий процес першого запуску й скидання: ідентичність, з’єднання, засіб відображення, головна інформаційна панель і вибір фільтра сутностей. |
| `/configure`                 | Налаштування засобу відображення й поведінки панелі.                                                                                              |
| `/profiles`                  | Вибір і перегляд профілів пристроїв та створення YAML.                                                                                            |
| `/entities`                  | Вивчення сутностей вбудованого засобу відображення, політика й перевизначення.                                                                    |
| `/install`                   | Програмне забезпечення, резервні копії, відновлення й обслуговування.                                                                             |
| `/logs`                      | Знеособлені поточні журнали застосунку.                                                                                                           |
| `/health` і `/api/v1/health` | Однорядковий звіт справності, описаний нижче.                                                                                                     |
| `/diag` і `/api/v1/diag`     | Текстовий діагностичний звіт. Перегляньте його перед поширенням.                                                                                  |
| `/ui`                        | Сокет, який використовують власні сторінки панелі. Це не інтерфейс скриптів, він може змінюватися між випусками.                                  |

Сторінки також завантажують свої скрипти, стилі й піктограми з панелі.

### Рядок справності

Рядок справності може містити `ha=<state>`, де стан — `normal`, `shutting_down`, `starting`, `back_online` чи `connection_lost`. Panel Assistant надсилає нативні сповіщення життєвого циклу; `connection_lost` означає розрив з’єднання без повідомлення про завершення роботи й відрізняється від навмисного вимкнення.

`ha_src=native` визначає стан життєвого циклу, спостережений через Panel Assistant. Локально визначені стани можуть пропускати цей токен. Джерело життєвого циклу MQTT не використовується.

Поки панель тримає автентифікований сокет Home Assistant з будь-якої причини (джерело сутності освітленості чи присутності Home Assistant або спостереження за реєстром), рядок справності також повідомляє виміряне з’єднання з Home Assistant. `ha_net=<healthy|warning|severe>` — висновок за рухомим п’ятихвилинним вікном про **мережевий шлях**: попередження, якщо понад 5% проб у вікні залишилися без відповіді; серйозний стан, якщо без відповіді дві послідовні проби. Затримка повного обміну ніколи його не підвищує, бо також включає час відповіді самого Home Assistant і планування потоків панелі; на дротовій панелі вона може показувати сотні мілісекунд за фактичного шляху менш ніж дві. Цей показник класифікується окремо як `ha_resp=<healthy|warning|severe>`: попередження після 100 мс і серйозний стан після 1 000 мс; це лише спостереження продуктивності. `ha_net_p95=<ms>` — 95-й процентиль повного обміну проб ping власного WebSocket застосунку за методом найближчого рангу (`-1`, поки жодна проба не отримала відповіді); `ha_net_n=<count>` — проби у вікні; `ha_net_miss=<count>` — проби без відповіді; `ha_net_age=<ms>` — час від останньої відповіді на пробу (`-1`, якщо жодної не було). Останній показник відрізняє щойно підключений сокет від потоку, що перестав виконувати проби. Перші три хвилини після запуску застосунку повідомляється лише `ha_net=settling` без висновку, бо стартове навантаження змушує час обміну описувати панель, а не з’єднання. Один пропуск чи сплеск ніколи не викликає тривоги. Відмови з боку самого Home Assistant, як-от закриття чи відхилення з’єднання під час перезапуску або відхилений вхід, рахуються окремо й ніколи як втрати. Проба без відповіді, коли інші кадри продовжують надходити, зокрема запізніла відповідь на попередню пробу, означає зайнятий сервер, а не втрачений шлях: вона рахується як збій сервера, і спільний сокет залишається відкритим. Вимірювання належить автентифікованому сокету, а не наміру його мати: токени відсутні, доки панель фактично не підключилася й не увійшла, та знову відсутні після припинення (немає облікових даних, немає потреби в сокеті або з’єднання відмовилося від подальших спроб). Поки раніше активний сокет відновлюється, токени залишаються, бо пошкоджений шлях слід показувати саме під час пояснюваного ним збою. Тому здоровий стан завжди повідомляється явно, а не відсутністю показників. Звіт `/diag` містить обидва висновки в одному рядку `[ha-network]`; він ніколи не містить адреси Home Assistant, назви мережі чи окремого зразка. Поруч повідомляється друге незалежне вимірювання того самого шляху: панель надсилає невелику серію запитів ICMP echo на адресу, до якої фактично підключений її сокет Home Assistant, а `/diag` містить результат в одному рядку `[ha-path-probe]`. Ця проба періодична, а не постійна; її інтервал зростає, поки шлях підтверджує справність, і повертається до мінімуму, щойно щось виглядає неправильно. Вона повідомляє `state=unsupported`, якщо платформа не надає застосунку сокет ICMP, і `state=unproven`, доки echo фактично не отримав відповіді. Тиша до цього не рахується втратою, бо інакше Home Assistant за зворотним проксі чи на хості, що фільтрує ICMP, виглядав би повністю несправною мережею на цілком доброму з’єднанні. Проба echo лише повідомляється й не піднімає попередження панелі. Обидва діагностичні рядки також називають **сімейство адрес, на якому фактично підключено сокет** (`family=ipv4` чи `family=ipv6`), у кожному стані, включно з `unsupported`: знання використовуваного панеллю сімейства найважливіше, коли немає інших даних мережевого рівня 3. Це не адреса, ім’я хоста чи назва мережі.

Сторінка **Налаштування** може запустити звичайний браузерний вхід Home Assistant. Повернене посилання можна відкрити чи скопіювати в приватне вікно браузера, щоб не вводити облікові дані на панелі. Home Assistant перенаправляє на локальний зворотний виклик панелі; ha-paneld сам обмінює одноразовий код і ніколи не повертає браузеру токени доступу чи оновлення. Зворотний виклик доступний лише через ті самі перевірки довіреної локальної мережі й Host, що й решта HTTP-служби панелі, прив’язаний до адреси панелі, яка його почала, спливає через десять хвилин і надсилає відповіді `no-store`/`no-referrer`.

Служба свідомо використовує модель довіреної локальної мережі замість загальної автентифікації. Вона відхиляє вузли поза локальною мережею, недійсні заголовки Host і браузерні запити з невідповідними Origin чи Referer до маршрутизації. Тримайте HTTP-службу панелі в довіреній мережі й не відкривайте її безпосередньо в інтернет. Необов’язковий [посилений режим](/uk/manage/security-mode/) потребує фізичного доступу для захищених прямих запитів локальної мережі; [довідник безпеки](/uk/reference/security/) описує повну модель.

<a id="the-rest-api-is-deprecated"></a>

## REST API застарів

REST API у `/api/v1` застарів, і його довідник OpenAPI більше не публікується. Панель, яка більше не обслуговує шлях, відповідає `410` і `{"error": "gone"}`. REST API припиняє відповідати на панелі, щойно Panel Assistant більше його не потребує. Використовуйте Home Assistant для автоматизації й моніторингу.

## Сполучення й виявлення

ha-paneld оголошує `_ha-paneld._tcp.local.` із метаданими версії, можливостей, маршруту й зручної назви. Непрозорий токен проби для кожного відповідача дозволяє панелі перевіряти, що її власне поточне оголошення лишається видимим у локальній мережі; після повторних пропусків вона перебудовує відповідач з обмеженими повторами, а діагностика попереджає, якщо відновлення вичерпано.
