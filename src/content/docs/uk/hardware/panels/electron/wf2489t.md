Для описаних тут заводської прошивки та збірки постачальника не знайдено приміток виробника до випусків. Порівняння збірок фіксує спостереження за образами й пристроями.

:::note
Відомості про заводську прошивку отримано з дампа `/diag` користувача та роздрібної пропозиції ([звіт про SMT1019 на GitHub](https://github.com/panel-assistant/android/issues/8)). Відомості про прошивку постачальника надав інший користувач, який працює з цією збіркою та опублікував документацію виробника в [наступному звіті](https://github.com/panel-assistant/android/issues/106). Дані користувача підтверджують спосіб отримання root, допоміжний процес зі збереженням після перезавантаження та осі сирих кліматичних даних у збірці постачальника. Комплектний профіль не пройшов наскрізну перевірку; точність кліматичних показів і спосіб роботи з датчиком наближення VI530x ще потребують апаратних випробувань. Пристрою для локального тестування немає.
:::

Настінний планшет із дисплеєм 10.1 in та rk3576, виготовлений **Electron** (Shenzhen Electron Technology, ELC) на платі `WF2489T`, споріднений з [WF1589T](/uk/hardware/panels/electron/wf1589t/) на rk3576. Прошивка повідомляє `ro.product.odm.manufacturer=Electron` і бренд Apolosign — власну торговельну марку Electron. У роздрібній пропозиції, завдяки якій пристрій уперше потрапив сюди, його продають як ZHICAI SMT1019; «ZHICAI TECHNOLOGY» — назва магазину в цій пропозиції, а не виробника.

## Початковий доступ для налагодження

**Мережевий ADB через TCP-порт 5555 без комп’ютера: не підтверджено.** Наявність у власника запущеного Panel Assistant або прошивки з root не встановлює, як увімкнути налагодження на новій панелі.

**Початкову процедуру налагодження через USB також не встановлено.** Попросіть постачальника надати інструкції для вашої точної прошивки й підтвердити наявність USB-порту передавання даних. Якщо він надає налагодження через USB, скористайтеся [USB-інсталятором](/uk/install/install-over-usb/); не припускайте, що зарядний порт надає ADB. Перевіреної послідовності дій у заводському меню тут немає.

Перевірки root потребують уже робочого з’єднання ADB. Доступ root і початковий доступ для налагодження — окремі питання.

Безбрендовий SMT1019, RK3576_64GB, ZHICAI TECHNOLOGY SMT1019, ZX-SMT1019, Apolosign WF2489T, Electron WF2489T, Amazon ASIN B0GSWXPB9K. Збірки прошивки `ZX-SMT1019-R157-V1.0A` та `ZX-SMT1019-R157-V2.0`.

## Доступ root залежно від збірки прошивки

**Існують дві збірки прошивки, які відрізняються найсуттєвішим.** Роздрібний пристрій постачається із закритою виробничою збіркою без root. Постачальник також надає збірку `userdebug`, і один користувач перепрошив на неї пристрій. Усе, що потребує root, залежить від збірки панелі, тому спочатку перевірте її.

|                         | Заводська (виробнича)                                                                                                                                  | `userdebug` постачальника                                                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Збірка                  | `ZX-SMT1019-R157-V1.0A`                                                                                                                                | `ZX-SMT1019-R157-V2.0-…` (`Apolosign/WF2489T/WF2489T:14/…:userdebug/release-keys`)                                                                                                                                                      |
| Root                    | **Немає**; `su` відсутній                                                                                                                              | **Є**. `adb shell id` уже повертає `uid=0`, а форму застосунку `su 0 sh -c "<cmd>"` підтверджено на пристрої зі збереженням лапок. `su -c` відповідає `su: invalid uid/gid '-c'` — це невідповідність діалекту, а _не_ відсутність root |

Спільне для обох: Rockchip **rk3576** (`ro.product.device=WF2489T`), дисплей **1280×800** 10.1 in, приблизно 4 ГБ RAM і 64 ГБ сховища, Android **14**, `arm64-v8a`, **з** сервісами Google Play.

### Установлення на збірці `userdebug`

`/system` доступний лише для читання, хоча панель має root: або не змонтовано доступне для запису накладання, або ввімкнено dm-verity. Тому немає місця для допоміжного процесу зі збереженням після перезавантаження й підготовка зупиняється. Спочатку спробуйте перемонтувати без перезавантаження. Лише запасний варіант перезавантажує панель, і для цього потрібно бути перед нею: панель із захистом PIN не запустить застосунки знову, доки PIN не буде введено:

```bash
# Try this first — no reboot, and on a panel that already carries a scratch overlay it is the whole fix:
adb -s <panel-ip>:5555 root && adb -s <panel-ip>:5555 remount

# Only if that is refused. This REBOOTS the panel, so be in front of it and unlock any PIN afterwards:
adb -s <panel-ip>:5555 disable-verity && adb -s <panel-ip>:5555 reboot
adb -s <panel-ip>:5555 root && adb -s <panel-ip>:5555 remount
```

Після цього підготовка завершується й допоміжний процес зберігається після перезавантажень (підтверджено користувачем).

## Датчики та інтерфейси плати

Температуру, вологість і наближення ввімкнено нижче; освітленість і дві лінії GPIO ще не під’єднано. Власна документація виробника зазначає, що **температуру й вологість читають через `getevent`** як звичайні пристрої введення evdev, а не через драйвер I²C, і що _індекс_ події відрізняється між варіантами з датчиком світла та без нього. Тому зіставляйте за **назвою** пристрою, а не номером. Апаратні дані підтверджують кодування сирих кліматичних значень у сотих частках; фізична точність ще потребує порівняння з екраном виробника або еталонним датчиком.

| Функція                   | Де доступна                                                                                                                                                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Температура й вологість   | evdev `sun-ths` і `sun-hum` (I²C `0-0044:gxht30`). **Увімкнено:** кодування сирих значень у сотих частках підтверджено, фізичну точність — ні                                                                                          |
| Наближення (час прольоту) | `/dev/vi530x` (I²C `4-006c`). **Експериментально:** осі драйвера підтверджено, але повний шлях запуску й читання застосунку панелі не виконувався на пристрої. Відстань — `ABS_HAT1X` у **міліметрах**, дійсність показу — `ABS_WHEEL` |
| Освітленість              | evdev `lightsensor-level` (I²C `4-0048:ls_stk3x1x`)                                                                                                                                                                                    |
| RGB-світлодіод            | `/dev/ledjni`                                                                                                                                                                                                                          |
| Дві лінії GPIO            | `/dev/gpio_control`                                                                                                                                                                                                                    |

## Підтримка застосунком панелі

Комплектний профіль [`smt1019.yaml`](https://github.com/panel-assistant/android/blob/main/app/src/main/assets/device-profiles/smt1019.yaml) надає вузькому зіставленню підрядка пристрою `wf2489` пріоритет над ширшим зіставленням моделі `rk3576_u` профілю WF1589T, щоб `WF2489T` не перетинався з іншою панеллю rk3576. Він оголошує:

- **`hardware.led.mechanism: rk3576-ioctl-daemon`.** Скомпільований драйвер ioctl працює лише через автентифікований допоміжний root-процес. Перевірка поточного стану залишає світлодіод недоступним і неопублікованим, коли допоміжний процес не може керувати вузлом, як у повідомленому встановленні без `su`.
- **`platform.su_form: none`.** На заводській прошивці немає доступного застосунку `su`, тому функції, що потребують root (кнопки evdev, регулятори CPU, вимкнення екрана через `bl_power`), там недоступні.
- **`hardware.screen_off: daemon-blpower`.** Профіль використовує автентифікований допоміжний процес для вимкнення підсвічування через `bl_power`. Це повністю вимикає екран і дозволяє засобу відображення припинити малювання за ним. `ScreenController` послідовно переходить від демона до прямого root, а потім до нульової яскравості. Заводська прошивка без допоміжного процесу й прямого root використовує нульову яскравість; збірка з root без допоміжного процесу може використовувати прямий root. Оголошення цього способу коштує заводській конфігурації одного відхиленого з’єднання із сокетом на кожне вимкнення екрана. Наскрізного результату цього способу для SMT1019 не повідомлено.

Стандартні можливості Android, як-от яскравість, навігація, синтез мовлення та сутності Home Assistant, працюють на обох збірках. Профіль оголошує мікрофон, тому голосові функції доступні; власник повідомляє, що вони працюють. Заводське встановлення без `su` не може керувати світлодіодом або обладнанням, що потребує root. Збірка постачальника може використовувати автентифікований допоміжний процес; роботу керування світлодіодом підтверджено користувачем. Апаратних кнопок не виявлено.

**Датчик наближення експериментальний.** Драйвер VI530x нічого не повідомляє, доки його не запустить користувацький простір. Тому допоміжний процес перед читанням вимірювання виконує послідовність виробника: подавання живлення, ініціалізація, період і запуск. Дані користувача підтверджують, що `ABS_HAT1X` — відстань у міліметрах, а `ABS_WHEEL` повідомляє дійсність показу, тому сире значення 1896 означає близько 1,9 м. Застосунок панелі використовує немасштабовану відстань із тим самим покроковим налаштуванням на панелі та збереженим калібруванням, що й інші джерела наближення, тому не залежить від здогаданого порога чи полярності. Повний шлях запуску ioctl та читання допоміжного процесу ще не виконувався на пристрої; повідомте результат у [наступному звіті](https://github.com/panel-assistant/android/issues/106).

**Температура у приміщенні та Вологість у приміщенні ввімкнені.** Перевірений допоміжний root-процес читає пристрої введення GXHT30 `sun-ths` і `sun-hum`. Сутності приміщення ввімкнені типово й не публікують значень, коли допоміжний процес недоступний. Дані користувача (2026-08-14) підтверджують сире кодування: `sun-ths` використовує `ABS_THROTTLE` з межами від -4000 до 12500, а `sun-hum` — вісь `0x1d` з межами від 0 до 10000. Працююча панель повідомила 2479 і 5704. Ці значення відповідають сотим часткам градуса Цельсія й сотим часткам відсотка, але **не** встановлюють фізичної точності. Перш ніж покладатися на них, порівняйте їх з екраном виробника чи еталонним датчиком. `sensors.room_temp_offset_c` може виправити сталий температурний зсув через власне нагрівання панелі; він не виправить помилки масштабування чи калібрування вологості.

:::caution
**Підказки root у профілі описують заводську збірку, але не забороняють комплектний допоміжний процес.** `su_form: none` і `app_can_su: false` правильні для роздрібної прошивки. Коли потрібен комплектний допоміжний процес, застосунок панелі перевіряє фактичний root, а не вважає ці підказки доказом. Форма збірки постачальника `su 0 sh -c "<cmd>"` двічі досягла `uid=0` зі збереженням лапок, тому застосунок може встановити відповідний допоміжний процес без запису до `/system`. Заводська панель просто не проходить цю перевірку та залишається без змін. Окремий спосіб установлення допоміжного процесу зі збереженням після завантаження все ще потребує описаного вище перемонтування.
:::

## WebView

Обидві збірки мають **сервіси Google Play** і надають `com.google.android.webview` **124.0.6367.179**; це встановлено розпакуванням кожної ROM, а не припущено. Заводська виробнича збірка (`ZX-SMT1019-R157-V1.0A`, 2026-02-05) — справжня збірка `user`; збірка постачальника (`…-V2.0`, 2026-07-30) — `userdebug`. На панелі зі збіркою постачальника окремо спостерігали ту саму версію.

Оскільки Play присутній, **підтримуване виправлення — оновити _Android System WebView_ через Play Store**. Ця панель належить до класу WF1589T, а не до класу ручного встановлення NSPanel Pro та TPA10. Не встановлюйте тут вручну збірку `com.android.webview`: `framework-res.apk` указує лише `com.android.webview` як `availableByDefault`, тоді як установлений постачальник — пакет Google. Отже, фактичний список постачальників задає продуктове накладання, і вручну встановлений постачальник може просто не вибиратися.

Chrome 124 датований квітнем 2024 року й запускає поточний інтерфейс Home Assistant, тому це звичайне оновлення, а не аварійне виправлення порожньої інформаційної панелі, як на інших пристроях.
