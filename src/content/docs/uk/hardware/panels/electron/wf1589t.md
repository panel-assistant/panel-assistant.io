Для цієї панелі не знайдено приміток виробника до випусків прошивки. Відомості про прошивку на цій сторінці — спостереження за дослідженим пристроєм.

Найфункціональніша з повністю підтримуваних панелей: пристрій rk3576 із дисплеєм **10.1 in 1920×1200 (приблизно 226 ppi)**, **4 ГБ RAM**, **RGB-світлодіодом із прямим керуванням застосунком**, якому не потрібен root, набором шестиосьових датчиків руху та **сервісами Google Play**, завдяки яким WebView і застосунки оновлюються автоматично. Прошивка також надає власну панель навігації Android. Мікросхема NFC присутня, але неактивна. Зворотне дослідження виконано на працюючому пристрої (Android 14 `userdebug`, `adb root`).

## Початковий доступ для налагодження

**Мережевий ADB через TCP-порт 5555 без комп’ютера: не підтверджено.** Наявність у власника запущеного Panel Assistant або прошивки з root не встановлює, як увімкнути налагодження на новій панелі.

**Початкову процедуру налагодження через USB також не встановлено.** Попросіть постачальника надати інструкції для вашої точної прошивки й підтвердити наявність USB-порту передавання даних. Якщо він надає налагодження через USB, скористайтеся [USB-інсталятором](/uk/install/install-over-usb/); не припускайте, що зарядний порт надає ADB. Перевіреної послідовності дій у заводському меню тут немає.

Перевірки root потребують уже робочого з’єднання ADB. Доступ root і початковий доступ для налагодження — окремі питання.

## Отримання доступу adb і root

WF1589T постачається зі збіркою `userdebug` і Google Play, тому `adb root` працює безпосередньо, а `su` присутній, без пароля й прихованого входу. Світлодіод керується застосунком напряму (нижче), тому застосунок панелі використовує root лише для вимкнення підсвічування через комплектний `su`.

```bash
adb root                     # userdebug → root adbd shell
adb shell su 0 id            # uid=0 → root confirmed
```

:::danger
WF1589T має OTA-оновлювач (`com.elclcd.otaupdater`), який може скасувати ваші зміни. Увімкнувши adb, вимкніть його (з можливістю повернення) командою `adb shell pm disable-user --user 0 com.elclcd.otaupdater`. Див. [Зупиніть небажані оновлення](/uk/hardware/guides/firmware-backup-and-restore/#stop-unwanted-updates).
:::

## WebView: уже обслуговується Play

WF1589T має **Google Play**, тому, на відміну від NSPanel Pro та TPA10, WebView не потрібно встановлювати вручну. Оновіть _Android System WebView_ через Play Store або скористайтеся каналом розробки Play WebView, і він буде актуальним. Порівняння панелей див. в [Оновленні системного WebView](/uk/hardware/guides/update-the-webview/).

## Системна панель навігації Android

Прошивка WF1589T малює власну панель «Назад», «Додому» та «Останні». Для нової конфігурації комплектний профіль типово вибирає режим `Native`, який залишає ці елементи Android і не малює накладеної панелі чи смужки відкриття. Наявні збережені налаштування зберігаються. Можливість увімкнено через профіль, а не прив’язано до моделі в коді; інші профілі також можуть оголосити її після перевірки панелі навігації їхньої прошивки. Повноекранні налаштування засобу відображення й блокування інформаційної панелі Android усе ще можуть приховати системну панель.

## Щільність дисплея: збільште її

За заводської базової логічної щільності (160 dpi) Android відображає приблизно 1 dp на 1 px, тому кнопки, текст і картки інформаційної панелі **фізично крихітні й незручні для дотику**. Базове значення — орієнтир компонування Android, а не фізичні 226 PPI панелі. Застосунок панелі рекомендує 212 dpi для цієї моделі — перевірену початкову точку; пристосуйте її до кімнати та інформаційної панелі:

```sh
adb shell wm density 212        # ha-paneld starting point; `wm density reset` restores the 160-dpi base
```

За 212 dpi ефективне полотно становить приблизно 1449×906 dp. Вище значення збільшує сенсорний інтерфейс і показує менше вмісту інформаційної панелі; нижче діє навпаки.

## Світлодіод: `/dev/ledjni` (напряму з застосунку, без root)

`/sys/class/leds` не має вузла RGB (лише `mmc1::`). Передній RGB-світлодіод керується через символьний пристрій із загальним доступом на читання й запис та міткою `device`, до якого SELinux дозволяє доступ застосункам. Тому звичайний застосунок керує ним **без root чи допоміжного демона**. Це єдиний клас панелей, де світлодіоду не потрібен root.

Застосунок панелі керує ним через `Rk3576LedController` і публікує сутність світлодіода лише там, де відкривається `/dev/ledjni`.

Заводський пакет `com.gulukai.pwmlightdemo` також відкриває цей пристрій. Його служба переднього плану запускається під час завантаження й постійно перемикає сім кольорів, перезаписуючи команди застосунку панелі та спричиняючи розбіжність між останнім заданим станом Home Assistant і фізичним світлодіодом. Протокол пристрою не дозволяє зчитати стан, тому два застосунки не можуть спільно забезпечити достовірне керування. Профіль WF1589T позначає цю демонстрацію як рекомендовану до вимкнення в інтерфейсі [Пакети постачальника](/uk/manage/vendor-packages/), де вимкнення залишається свідомою зворотною дією.

### Вузол `/dev/ledjni` та протокол ioctl

```text
/dev/ledjni   crwxrwxrwx  system system  u:object_r:device:s0
```

Протокол ioctl незалежно відтворено за зразком виробника, жодного двійкового файла виробника не включено; див. [`led_jni.c`](https://github.com/panel-assistant/android/blob/main/app/src/main/cpp/led_jni.c):

```c
int fd = open("/dev/ledjni", O_RDONLY | O_NOCTTY);
ioctl(fd, 0xa1, R);   // red,   0..15
ioctl(fd, 0xa2, G);   // green, 0..15
ioctl(fd, 0xa3, B);   // blue,  0..15
ioctl(fd, 0x99, 0);   // off
close(fd);
```

## Датчики: шестиосьові датчики руху через `SensorManager`

Незвично для настінної панелі, WF1589T надає повний набір датчиків руху через стандартний `SensorManager`, без root: `accelerometer`, `gyroscope`, `gravity`, `linear_acceleration` і `game_rotation_vector`. Апаратна основа — акселерометри Kionix **KXTJ9** і Bosch **BMA2xx**. `TYPE_LIGHT` і `TYPE_PROXIMITY` не надаються, бо відповідних датчиків немає.

На цій платі немає прив’язаних датчиків освітленості, наближення, температури чи вологості (порівняйте з [TPA10](/uk/hardware/panels/tuya/tpa10/), де є всі чотири).

## Камера

GalaxyCore **GC05A2** (I²C `4-0037` у таблиці вище), сенсор 2592×1944. Android повідомляє одну камеру апаратного рівня `LIMITED`, лише `BACKWARD_COMPATIBLE`, `Facing: Front`, без спалаху й автофокуса, через постачальника `internal/0-1`. Другий постачальник `external/0-0` присутній без під’єднаних пристроїв; панель оголошує `android.hardware.camera.external`.

1280×720 доступне у всіх трьох форматах: `IMPLEMENTATION_DEFINED`, `YUV_420_888` і `BLOB`. HAL оголошує затримку на один кадр для знімка `BLOB` 720p за 30 fps. Цей показник виробника для фотознімка не вимірює вартість потоку H.264 застосунку панелі. `android.control.aeAvailableTargetFpsRanges` пропонує лише `[15 30]` і `[30 30]`: фіксованого режиму сенсора 15 fps немає, тому потік 15 fps отримується обмеженням темпу кодувальника, а не сенсора.

Апаратний кодувальник H.264 — `c2.rk.avc.encoder`, який обслуговує Codec2 HAL (`android.hardware.media.c2@1.1-service`; процесу OMX `media.codec` на цій панелі немає). Він має псевдонім `OMX.rk.video_encoder.avc`, тому вибір за назвою знаходить _щось_ і на цій панелі, і на TPA10. Проте це різні компоненти по різні боки переходу від OMX до Codec2, і не слід припускати однакової поведінки. Він оголошує від `176x144` до `4096x2160` з вирівнюванням `2x2`, повідомлений діапазон бітрейту від 1 bps до 20 Mbps і 32 одночасні екземпляри. На відміну від TPA10, ця панель також має апаратний кодувальник HEVC `c2.rk.hevc.encoder`, який застосунок панелі не використовує.

Панель, що показує картки камер, не простоює. На виміряній інформаційній панелі застосунок утримував два активні екземпляри `c2.rk.avc.decoder`, тому сеанс кодування конкурує з декодуванням на тому самому Rockchip VPU.

Застосунок панелі може надавати цю камеру як функцію, **типово вимкнену**. Перемикач **Камера** на картці камери в **Налаштування** вмикає її з типовими параметрами **Роздільна здатність**, **Частота кадрів** і **Бітрейт** (720p, 15 fps, 2000 kbps) та зміщенням **Експозиція**. Потік H.264 надається за `rtsp://<panel>:8554/live`, зі звуком кімнати, коли мікрофон доступний і дозвіл надано. Home Assistant отримує знімки з цього потоку через сутність камери панелі. Щоразу, коли камера відкрита, панель показує червоний індикатор, який вміст сторінки не може закрити. Сутність камери описано в [довіднику керування](/uk/reference/api/).

:::caution
Не розміщуйте картку камери Home Assistant **цієї** панелі на інформаційній панелі **цієї ж** панелі. Панель без користі декодуватиме власний закодований потік по колу на тому самому відеорушії.
:::

## NFC: присутній, але не під’єднаний до Android

**Контролер NXP NFC** прив’язано на `i2c-7 0x28` (драйвер `nxpnfc`) із вузлом `/dev/nxpnfc` (`crw------- root root`). Однак `pm list features` **не** повідомляє `android.hardware.nfc`: служба Android NFC і HAL не ввімкнені в цій прошивці. Мікросхема є, але в поставленому стані неактивна для застосунків. Для її використання потрібні NFC HAL і NfcService або прямий доступ до `/dev/nxpnfc` як root. Застосунок панелі її не використовує.

## Підсумок моделі доступу

- **Світлодіод:** напряму з застосунку (`/dev/ledjni`), без root і демона.
- **Датчики руху:** напряму з застосунку (`SensorManager`).
- **NFC:** присутній (NXP), але Android NFC вимкнений; у поставленому стані лише root.
- **Навігація:** власна панель навігації Android через режим `Native` профілю.
- **Яскравість екрана, навігація, синтез мовлення:** стандартні способи Android, як на будь-якій панелі.
- **Вимкнення екрана:** вимкнення живлення підсвічування через комплектний `su`.
